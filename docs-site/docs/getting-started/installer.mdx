# One-line installer

`setup-openprocessor.sh` installs a pinned OpenProcessor release into its own
directory: no git clone, no local image build, no host Python.

```bash
curl -fsSL https://raw.githubusercontent.com/davidamacey/OpenProcessor/main/setup-openprocessor.sh | bash
```

The script you pipe in only resolves the release, downloads that release's own
`setup-openprocessor.sh` and `SHA256SUMS`, checks the checksum and runs the
verified copy. A truncated download is a syntax error before anything runs.
The installer then:

1. downloads the release bundle and checks every file against `SHA256SUMS`;
2. checks Docker, Compose, the GPUs and free disk, asks which tiers you want
   (or takes `--tiers`) and plans GPU placement. The prompt is a numbered menu:
   `1` the tiers recommended for this machine (the default, so Enter takes it),
   `2` core only, `3` curation with the Cropwright web UI, `4` everything, `5` a
   custom comma-separated list. Dependencies are added automatically; an invalid
   answer asks again and the third one exits with a usage error. The plan picks
   the `full` Triton profile only for a card with 40 GB or more free (see
   [GPU sizing](../deployment/gpu-sizing.mdx));
3. writes `.env` (mode 600): tiers as `COMPOSE_PROFILES`, ports, image
   digests from `images.lock`, the GPU plan and the OpenSearch heap. It never
   changes a value you set yourself;
4. pulls the images and checks each digest against `images.lock`;
5. exports the TensorRT engines inside the containers (engines already on disk
   that Triton loads are kept, not rebuilt), starts everything and runs a health
   check;
6. prints a summary with the URLs, the OpenSearch heap and shard budget, the
   security note and the management commands.

**Needs:** Linux, Docker with Compose v2, an NVIDIA GPU with the NVIDIA
Container Toolkit, and disk for the tiers you pick. The installer never
installs packages or changes the Docker daemon config: it tells you what is
missing and stops.

Not sure which tiers to pick? See [Choose your path](./choose-your-path.mdx).

## Tiers

| Tier | What you get | Extra images | Needs |
|---|---|---|---|
| `core` | Triton, the API (port 4603), OpenSearch | ~42 GB | ~16 GB VRAM (`--profile minimal` for 6-8 GB cards, `small` for 12 GB cards) |
| `curation` | curation workers, PE-Core embeddings, evaluator | + ~0.3 GB | + ~2 GB VRAM; implies `core` |
| `segmenter` | SAM 3 segmenter | + ~8 GB | 2-8 GB VRAM; a HuggingFace token with SAM 3 access (gated); implies `curation` |
| `vlm` | local vLLM serving a model from the VLM catalog | + ~19 GB | ~23 GB VRAM for the default; implies `curation` |
| `trainer` | training service + MLflow | + ~9 GB | at least 16 GB free VRAM while training; implies `curation` |
| `cropwright` | the Cropwright web UI (a profile of the same compose project) | + ~65 MB | implies `curation` |

Monitoring (Prometheus, Grafana, Loki, Alloy) is not a tier: add
`--with-monitoring`. Its dashboards are default-open, so it is off unless you
ask. See [Compose profiles](./compose-profiles.mdx) for what each profile
starts.

## Unattended install

```bash
curl -fsSL https://raw.githubusercontent.com/davidamacey/OpenProcessor/main/setup-openprocessor.sh \
  | bash -s -- --tiers core,curation,cropwright --unattended
```

`--unattended` never prompts. A step that needs consent fails unless its
consent variable is set:

| Variable | Allows |
|---|---|
| `OP_ALLOW_PUBLIC_BIND=1` | a non-loopback `--bind` |
| `OP_ALLOW_EXTERNAL_VLM=1` | a `--vlm-remote` URL outside private address space |
| `OP_CONFIRM_PURGE=<project>` | `--purge-volumes` / `--purge-data` |

Other common flags: `--all` (every tier), `--version vX.Y.Z` (pin a release),
`--dir PATH`, `--project NAME`, `--port-base N`, `--sample-data`,
`--skip-models` (start without exporting models; the API answers 503 until they exist), `--no-start`, `--dry-run` (print every state-changing command, run none).
`INSTALLATION.md` in the repository lists every flag.

## Verify the download yourself

```bash
V=vX.Y.Z   # the release you want
curl -fsSLO https://github.com/davidamacey/OpenProcessor/releases/download/$V/setup-openprocessor.sh
curl -fsSLO https://github.com/davidamacey/OpenProcessor/releases/download/$V/SHA256SUMS
grep ' setup-openprocessor.sh$' SHA256SUMS | sha256sum -c -
bash setup-openprocessor.sh --version "$V"
```

`SHA256SUMS` comes from the same place as the files it covers. It proves
**integrity** (the download is complete and uncorrupted), **not
authenticity**. The same holds for `images.lock`, which
pins exact digests and are covered by `SHA256SUMS`; the installer also checks
that each `images.lock` entry names the image repo expected for its key.
Signed releases are follow-up work.

## Where your images go

The installer sets `OP_SOURCE_ROOT_HOST=./data`, so the install's `data/` directory is the source root, the
folder the API and the workers read images from (`/data/source` inside the containers). To point it at your
own images, edit it in `.env` and run `./openprocessor start`; see
[Basic configuration](../configuration/basic.mdx) for the variable and the services to recreate.

## Cropwright in the bundle

Cropwright is built from `frontend/` in this repository and released with the backend.
Its image (`davidamacey/cropwright`) is pinned in `images.lock` like every other image,
and the `cropwright` tier is a profile of the main compose project, so the installer
needs nothing from a second repository. Its port and bind address go in the install
`.env` as `OP_CROPWRIGHT_PORT` and `OP_CROPWRIGHT_BIND_ADDRESS`.

The Cropwright documentation is a section of this docs site, and its UI links into it.
The `/OpenProcessor/` route of Cropwright's nginx proxies to the docs container
(`docker-compose.docs.yml`) and answers 502 unless that container is running.

## Network access

Cropwright is reachable on your LAN by default behind a shared HTTP basic-auth login (user `cropwright`,
password in `secrets/cropwright/password`); the API stays on 127.0.0.1. `--local-only` keeps everything on
loopback, and `--bind <ip>` publishes the backend ports after a warning and a typed `expose`. Never
port-forward any OpenProcessor port to the public internet. The full rules, the password command and the
re-run behaviour are in [Security](../deployment/security.mdx#lan-access-from-the-one-line-installer).

## Local VLM management

With the `vlm` tier installed, the `openprocessor` CLI in the install
directory switches the model the in-compose vLLM serves and stores keys for
remote endpoints:

```bash
./openprocessor vlm list                 # the local model catalog
./openprocessor vlm status               # catalog id, served and desired model
./openprocessor vlm use <id> [--force] [--yes]
./openprocessor vlm apply                # apply a model chosen through the API
./openprocessor vlm probe                # re-probe the in-compose endpoint
./openprocessor vlm key set <slug>       # store an API key as secrets/vlm/<slug>
./openprocessor train-mode on        # stop the VLM around training
./openprocessor train-mode off       # start it again
```

`vlm use` checks the model fits the card, refuses while a training run
holds the GPUs, pauses the workers, rewrites the `VLM_*` keys in `.env` (restoring them if
anything fails), recreates the container, waits until the new model is
served and probes it. See [VLM selection](../guides/vlm-selection.mdx).

## OpenSearch heap sizing

The installer sets `OPENSEARCH_HEAP` to half of host RAM (2 to 30 GB) and never
overwrites a value you set. The table, the shard budget and the kernel setting are on
[Memory, disk and storage](../deployment/sizing-and-storage.mdx#opensearch-heap-and-shards).

## Upgrade, repair, rollback, uninstall

Run `./openprocessor upgrade`, `./setup-openprocessor.sh --repair`, `--rollback` and `--uninstall` from the
install directory. What each does, the backups and the data backup are in
[Upgrade, repair and back up](../operations/upgrade-and-backup.mdx).

## Troubleshooting

| Exit code | Meaning |
|---|---|
| 2 | usage error (or a port conflict you declined: use `--port-base N`) |
| 3 | project or container-name collision: pass `--project NAME` or another `--dir` |
| 4 | no usable GPU, or the GPU plan was refused |
| 5 | Docker unreachable |
| 6 | HuggingFace token missing or rejected (accept the SAM 3 license first) |
| 7 | checksum, digest or `images.lock` verification failed |
| 8 | health check or model setup failed: check `./openprocessor logs`, then `--repair` |
| 9 | consent not given: re-run with `--yes` or the consent variable |

There is no CPU inference path for the detection, face and image-embedding models (the small text encoders run on CPU). `--cpu --control-plane-only` is an optional
mode (never the default) for a machine with no usable GPU. It starts only
OpenSearch and the API, plus Cropwright if requested. It does not start Triton,
the curation workers, the VLM, the segmenter, the trainer or monitoring. Use it
to browse an existing index or when the models run elsewhere. Anything needing
local inference answers 503 and the API reports `degraded`.
