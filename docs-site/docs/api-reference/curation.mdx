# Curation routes

:::info[Experimental]
The curation subsystem is experimental in v0.4.0. It is real and tested,
but backward compatibility across releases is not guaranteed until it
graduates. It ships opt-in behind the `curation` compose profile.
:::

The generated contract, `contracts/openapi/curation.json`, lists **237
method routes** and is the source of truth for every path, parameter and
schema. This page groups them by area. Request models reject unknown keys
(`extra='forbid'`), so a stale or misspelled field is a `422`, never a
silent no-op. Consumers should read the mount prefix (`OP_API_PREFIX`,
default `/curation`) from configuration rather than hardcode it. There is no
`/v1` twin and no alias.

## Projects and scoping

A [project](../guides/projects.mdx) is an isolated dataset workspace with
its own indexes, class registry, exports, settings and job state. Every
route that reads or writes data lives under
`/curation/projects/{project}/`. There is no unscoped alias: an unscoped
data path is a `404`. Paths on this page omit that prefix unless they are
global.

The routes outside a project:

| Method | Path | Purpose |
|---|---|---|
| GET | `/curation/health` | Deployment facts only: `status`, Triton, OpenSearch, VLM, versions |
| GET | `/curation/events` | Server-sent events with `project: null`: `project.*`, `combine.*`, `vlm.changed` |
| GET | `/curation/projects` | List projects (`?include_archived=true`), shard capacity, slug limits, display labels |
| POST | `/curation/projects` | Create a project (`slug`, `display_name`, optional `description`, `clone_settings_from`, `clone_axes`). `201` |
| GET | `/curation/projects/{project}` | One project: status, revision, counts, resources, flags (`writable`, `deletable`, ...) |
| PATCH | `/curation/projects/{project}` | Edit `display_name` / `description`; needs `expected_revision` |
| POST | `/curation/projects/{project}/archive` | Archive (read-only). `/unarchive` reverses it |
| POST | `/curation/projects/{project}/clone_settings` | Copy settings axes from another project |
| DELETE | `/curation/projects/{project}` | `?dry_run=true` reports what would go; a real delete needs `?confirm=<slug>` and answers `202` |
| GET | `/curation/vlm/endpoints` | The VLM endpoint registry (see [VLM endpoints](#vlm-endpoints)) |
| GET | `/curation/vlm/catalog` | The local VLM catalog |

A project's `status` is `building`, `active`, `archived`, `deleting`,
`deleted` or `failed`. Only an `active` project is writable; an archived one
answers writes with `409 project_read_only`. The `default` project is an
ordinary project that can be archived but never deleted. Lifecycle
mutations answer one envelope, `{project, warnings}`, so a client can adopt
the returned summary without a re-read.

Errors from project, config and import routes share one body,
`{"detail": {"error": "<code>", "message": "...", ...}}`, with
code-specific extra fields. Read endpoints **fail closed**: a backend error
is an HTTP error, never a silently empty result.

## Ingest

Ingest runs the configured item detector, crops each detection into an
item, embeds it, rejects duplicates and indexes in bulk. Images are read
from configured source roots or uploaded as bytes. To import an
already-labeled dataset, use [Dataset import](#dataset-import).

| Method | Path | Purpose |
|---|---|---|
| POST | `/ingest/image` | Ingest one image by `path` (under a configured source root) |
| POST | `/ingest/batch` | Ingest `items` by path; capped by `OP_BATCH_MAX_ITEMS_PER_REQUEST` (`413` over it) |
| POST | `/ingest/upload` | Multipart upload of `images`; bytes are persisted content-addressed under the project's upload root; optional `run_id` |
| POST | `/ingest/path_lookup` | Which image paths (or upload identifiers) are already indexed |
| GET | `/ingest/config` | Served upload/batch limits and drain-poll parameters |
| GET | `/ingest/status` | Totals by source and day (optionally `?run_id=`) |
| GET | `/ingest/region_drain` | Pending region work, a stability verdict (`drained`), per-dependency health and a `stall_reason` |

Each image result carries `status` (`success` / `duplicate` / `failed`),
`image_id`, `n_crops`, `n_regions`, and on failure an `error_kind`
(`empty`, `unservable_path`, `unsupported_type`, `decode_failed`,
`detector_infer`, `bulk_index`, ...). Byte-identical files are
deduplicated within a batch as well as against the index.

## Dataset import

Bring a labeled YOLO or COCO dataset, or an OpenProcessor export, into a
project. Classes map **by name**. The import is chunked, resumable and
undoable. See [Dataset import](../guides/dataset-import.mdx).

| Method | Path | Purpose |
|---|---|---|
| GET | `/datasets/formats` | The formats the importer reads |
| POST | `/datasets/uploads` | Upload a zip or tar archive (`201`, `413 upload_too_large`) |
| POST | `/datasets/preview` | Scan a dataset without writing: classes, counts, issues, and `suggestions` for the class mapping |
| POST | `/datasets/imports` | Start an import. `202`; `reused` when the same `import_key` already ran |
| GET | `/datasets/imports` | List imports |
| GET | `/datasets/imports/{import_id}` | Status, progress and the report |
| GET | `/datasets/imports/{import_id}/issues` | The scan issues, paged |
| GET | `/datasets/imports/{import_id}/entries` | Per-image ledger rows, paged |
| POST | `/datasets/imports/{import_id}/cancel` | Stop after the current chunk |
| POST | `/datasets/imports/{import_id}/resume` | Continue an interrupted or cancelled import (`202`) |
| POST | `/datasets/imports/{import_id}/undo` | Reverse the import |

The mapping is a list of `{dataset_class, action, ...}` rows where `action`
is `map` (`class_id`), `create` (`new_class_name`, `new_class_group`), `skip`
or `region`. Every class that has boxes needs a decision
(`422 class_mapping_incomplete` lists the `unmapped` names). A COCO layout
(`images/` next to `annotations/*.json`) is detected automatically.

## Reprocess

One route re-runs pipeline stages over existing data. See
[Reprocess](../guides/reprocess.mdx).

| Method | Path | Purpose |
|---|---|---|
| POST | `/reprocess` | `targets` (exactly one of `image_ids`, `crop_ids`, `filter`), `scopes` (`detect`, `region`, `vlm`, `embed`), `region_mode` (`redetect` / `reverify`), `dry_run` (default `true`) |
| POST | `/images/{image_id}/reprocess` | The per-image button; applies by default |
| POST | `/crops/{crop_id}/reprocess` | The per-item button; applies by default |
| GET | `/reprocess/jobs/{job_id}` | Progress of a job (`detect` or `embed` beyond `OP_REPROCESS_SYNC_MAX` images runs as a file-backed job; one live job per project, `409 reprocess_busy`) |
| POST | `/reprocess/jobs/{job_id}/cancel` | Stop a live job after its current chunk |

Locked items and boxes are never written; each scope reports
`locked_skipped`. The filter also selects by provenance: `profile_not`,
`profile_revision_below`, `import_id`, `dataset_split`, `region_status`,
`reason`, `detector`, `missing_status`, `missing_provenance`.

## Combining projects

`POST /curation/projects/combine` builds a NEW project from 1 to 8 existing
ones. It never writes to a source: the target is created `building`,
filled, then made `active` (a failed run leaves it `failed`; deleting the
target is a complete undo). These routes are global, not under a project.
See [Combine projects](../guides/combine-projects.mdx).

| Method | Path | Purpose |
|---|---|---|
| POST | `/curation/projects/combine/preview` | Dry run (writes nothing): errors and warnings, `suggested_mapping`, per-source and target counts, duplicate and conflict counts, bytes to link, and a `preview_sha` |
| POST | `/curation/projects/combine` | Start with the preview body plus `expected_preview_sha` (`409 preview_stale` if a source changed, `422 combine_invalid` with a report). `202 {job_id, target}` |
| GET | `/curation/projects/combine/{job_id}` | `status`, `phase`, `done` / `total` images, `report`, `next_steps`; also published as `combine.progress` events |
| POST | `/curation/projects/combine/{job_id}/cancel` | Cancel a running job |
| POST | `/curation/projects/combine/{job_id}/resume` | Resume an interrupted or cancelled job from its last finished chunk |

A class is its name. `class_mapping` has one list of `map` / `create` /
`skip` / `region` rows per source, the same rows a dataset import takes;
every source class with an included label needs a row (`unmapped_class`).
The target numbers its own classes. Sources are listed in priority order.
With `dedup: content_hash`, an image that is byte-identical in two sources is
copied once, from the highest-priority source; boxes of the other copy with
IoU of at least `dedup_iou` and the same target class are merged (the more
trusted label wins: human, import, VLM, model), and a box with a different
class keeps the priority label and is flagged `combine_conflict`
(the `combine_conflict` filter on `GET /review/{tab}` lists them). Clusters are not
copied: recluster the combined items. `holdout: preserve_union` keeps
anything that was test in any source as test; `recompute` picks a new split
and warns. A live combine marks its sources and target `project_busy`.

**The lock rule.** A human-set class, a validated imported label, an item
in the frozen test holdout, and a human-owned or imported-and-settled
region box are locked. No automated writer (worker, VLM batch, re-ingest,
reprocess, import over an existing item) changes a locked value. A human
label always writes `class_source: "human"`; a client cannot make a human
write look machine-made. An item serves `label_locked`.

## Classes

Class identity is the **name**. A project's registry assigns its own ids;
a dataset, a combined source or a promoted model is matched to it by name.

| Method | Path | Purpose |
|---|---|---|
| GET | `/classes` | List with counts, thresholds and reserved hotkeys |
| POST | `/classes` | Create (`name` must match `^[a-z0-9_]+$`) |
| GET | `/classes/{class_id}` | One class |
| PUT | `/classes/{class_id}` | Rename, regroup, bind or clear a hotkey |
| GET | `/classes/{class_id}/crops` | Items of a class |
| POST | `/classes/merge` | Merge `source_id` into `target_id`; `?dry_run=true` previews |
| POST | `/classes/{class_id}/deprecate` | Retire a class that has no data yet |
| POST | `/classes/{class_id}/restore` | Restore it |
| POST | `/classes/sync_to_opensearch` | Re-sync the JSON registry into the classes index |

The registry is a JSON file in the project's data directory; the first
`POST /classes` creates it with dense ids starting at 0. A hotkey that the
project's keymap reserves answers `422 hotkey_reserved`; one that another
class holds answers `409 hotkey_taken`.

Each project stores its own keyboard map; a project with no stored map

| Method | Path | Purpose |

| POST | `/keymap/validate` | Dry run of a PUT; always `200` with a report |
| POST | `/keymap/reset` | Reset all or the listed actions |

## Regions of interest

is active. An item carries a **list of boxes** (`region_boxes`), each with a
`box_id` and its own state, verdict, text, cluster and embedding; see
[Multi-box regions](../guides/multi-box-regions.mdx). A profile's
`max_regions_per_item` caps the list (default `1`).

| Method | Path | Purpose |
|---|---|---|
| GET | `/regions` | Browse region rows: one row per matching box, or per item. `total` counts items, `total_rows` rows. Filters include `box_state` |
| GET | `/regions/statuses` | The status catalog, the per-box state vocabulary and which are human-writable |
| GET | `/regions/vocabulary` | Detector, segmenter and verifier vocabulary for the active profile, with `limits.max_boxes_per_write` |
| PUT | `/crops/{crop_id}/regions` | Set a crop's box list (`frame` `source` or `parent`). A box with only a `box_id` is left untouched; `box_id: null` adds a box. A stale `expected_region_revision` is `409 region_conflict`; an empty list means "no region visible" |
| PUT | `/crops/batch_regions` | Add the same new boxes to many crops |
| PATCH | `/crops/{crop_id}/regions/{box_id}` | Patch one box's `state` or `text` without touching its siblings |
| POST | `/regions/batch_box_state` | Set one state on many `{crop_id, box_id}` targets |

## VLM endpoints

The endpoint registry is deployment-wide; which endpoint a project runs is
per project. The registry is global, so these routes are not under a
project. Keys are never stored or served: an endpoint holds an
`api_key_ref` such as `secret:<slug>`. See
[VLM selection](../guides/vlm-selection.mdx).

## VLM and auto-label pipeline

Every VLM route takes an optional `?vlm=<name>` or `<name>@<revision>` and
`?acknowledge_external=`; an unknown name is `422 unknown_vlm`, and a
project with the VLM off is `409 vlm_not_configured`.

| Method | Path | Purpose |
|---|---|---|
| POST | `/vlm/label_batch` | VLM class suggestions for up to 64 `crop_ids` |
| POST | `/vlm/label_cluster/{cluster_id}` | VLM-label one cluster's members, as a background job |
| POST | `/vlm/verify_regions` | Verify, box by box, whether each crop's regions are real |
| POST | `/vlm/verify_region_batch` | The same in batches per upstream call |
| POST | `/vlm/region_visible_batch` | "Is a region visible at all?" pre-filter |
| POST | `/pipeline/auto_label/start` | Queue a job for the auto-label worker (`run_vlm`, `train_clusters`, ...). Clusters only unless `run_vlm=true` |
| GET | `/pipeline/auto_label/status` | Current or last job |
| GET | `/pipeline/auto_label/status/{job_id}` | One job |
| POST | `/pipeline/auto_label/cancel` | Cancel |
| POST | `/pipeline/auto_label` | Run the pipeline in-process (synchronous) |
| GET | `/pipeline/events` | Pipeline progress events |

negative verdict, so the item can be retried.
