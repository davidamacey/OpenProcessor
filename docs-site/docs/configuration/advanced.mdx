# Configuration: advanced

Grouped by area, in roughly the order `env.template` lists them. Every
variable is optional; defaults are shown where `env.template` states one.
`env.template`'s inline comments carry the full detail. Retired vendor- or
company-prefixed names are rejected loudly at startup (see
`src/config/retired_env.py`), as is the old `OP_DETECTION_*` prefix.

The common variables are on [Basic configuration](./basic.mdx).

## Projects

A [project](../guides/projects.mdx) is an isolated dataset workspace. The
variables below are read when a project is **created** and persisted in its
record; changing them later does not move an existing project. The
`default` project is created at first boot like any other.

| Variable | Default | Meaning |
|---|---|---|
| `OP_PROJECTS_INDEX` | `op_projects` | Index holding the project records |
| `OP_PROJECT_INDEX_PREFIX` | `op_prj_` | Prefix of every project index |
| `OP_PROJECTS_DATA_ROOT` | `./data/projects` | Parent of each project's class registry, exports and bake-off eval sets |
| `OP_SHARDS_PER_HEAP_GB` | `20` | Shards per GB of OpenSearch heap, for the soft shard budget. Past the budget, creating a project only warns; it is not a cap |
| `OP_CURATION_PROJECT` | `default` | The project a worker or script binds when it has no `--project`. Not meant to be set for the API server |

What a project owns, resolved from those variables and the roots below:

| Resource | Location |
|---|---|
| OpenSearch indexes | `{OP_PROJECT_INDEX_PREFIX}{slug}__{role}` for `images`, `items`, `labels_confirmed`, `classes`, `umap_state` and `configs`. Settings and projection state share the `configs` index |
| Class registry | `{OP_PROJECTS_DATA_ROOT}/{slug}/class_registry.json` |
| Exports | `{OP_PROJECTS_DATA_ROOT}/{slug}/exports/` |
| Bake-off eval sets | `{OP_PROJECTS_DATA_ROOT}/{slug}/bakeoff_eval/{curated,public,sample}` |
| Uploads, state, bake-off job queue | `{OP_STATE_DIR}/projects/{slug}/` (`uploads/`, `bakeoff_jobs/`) |
| Training job files | `{OP_TRAIN_JOBS_DIR}/projects/{slug}/` |
| Auto-label job state | `{OP_AUTO_LABEL_STATE_DIR}/projects/{slug}/` |
| MLflow experiment | `openprocessor-{slug}` |
| Promoted-model prefix | `{slug}__` (empty for `default`) |

There are no variables for individual index names, the class registry file,
the export root, the upload root or the eval root. Indexes are created
automatically; there is no manual migration step.

## Image names

`OP_IMAGE_REPO` and `OP_IMAGE_TAG` are on the basic page. Each built

## Ingest item detectors

`OP_INGEST_PRIMARY_<FIELD>` configures the required primary (an end2end,
already-NMS'd proposer); `OP_INGEST_SECONDARY_<FIELD>` an optional
raw-output detector whose IoU-matched hits override the primary's class.
Field names come from the `DetectionProfile` dataclass; tuple fields take
a comma-separated value. These are deployment settings shared by every
project.

| Variable | Example / default |
|---|---|
| `OP_INGEST_PRIMARY_DETECTOR_MODEL` | `yolov11_small_trt_end2end` (required) |
| `OP_INGEST_PRIMARY_INPUT_SIZE` | `640` |
| `OP_INGEST_PRIMARY_CONFIDENCE_FLOOR` | `0.4` (only when the primary assigns classes; a proposer stores every detection the engine emits) |
| `OP_INGEST_PRIMARY_CLASS_IDS` | Retired and ignored with a warning. Narrow ingest per project with the ingest policy instead |
| `OP_INGEST_PRIMARY_ASSIGNS_CLASS` | `false` |
| `OP_INGEST_PRIMARY_LABELS_PATH` | the proposer's `labels.txt`, recorded as each item's proposal name |
| `OP_INGEST_PRIMARY_NAME` | `item` |
| `OP_INGEST_PRIMARY_LETTERBOX_FILL` | `114,114,114` |
| `OP_INGEST_SECONDARY_DETECTOR_MODEL` | unset (off) |
| `OP_INGEST_SECONDARY_DETECTOR_VERSION` / `_INPUT_SIZE` / `_CONFIDENCE_FLOOR` / `_NAME` | `1` / `640` / `0.4` / `secondary` |

## Region detection profile

Off by default: with none of these set and no profile activated in a
project, no region profile is active, `GET /curation/projects/{project}/methods`
advertises no detection profile, and the detection worker idles for that
project. No profile ships built in.

These variables define the **deployment default**. A project replaces it
by activating a stored profile
(`POST /curation/projects/{project}/region_profiles/{name}/activate`); see
[Region profiles](../guides/region-profiles.mdx). `PUT .../settings` with
`defaults.detection_profile` delegates to the same activation (`off`
deactivates).

| Variable | Meaning |
|---|---|
| `OP_REGION_PROFILE_PATH` | Load a profile JSON. This is a **container** path; compose mounts `./examples` at `/app/examples` read-only. `examples/region_profiles/` holds worked examples, including `vehicle_wheel.json` |
| `OP_REGION_PROFILE` | Select a profile your own startup code registered by name (an unknown name fails at startup) |
| `OP_REGION_DETECTION_<FIELD>` | Per-field overrides, e.g. `_NAME`, `_DETECTOR_MODEL`, `_SEGMENTER_TEXT_PROMPT`, `_SECONDARY_SHAPE_GROUPS` |
| `OP_REGION_DETECTION_TEXT_READER` | `vlm`, `ocr`, `vlm_then_ocr` (default), `both`, or `none` for a text-free region |
| `OP_REGION_DETECTION_TEXT_*` | Dominant-text rules: `_MIN_HEIGHT_RATIO`, `_BORDER_MARGIN`, `_CHARSET`, `_STOPWORDS`, `_FORMAT`, `_PLACEHOLDERS`, `_REJECT_SEQUENCES` |
| `OP_ITEM_TEXT_ENABLED` / `OP_ITEM_TEXT_MIN_CONFIDENCE` | Store OCR lines read on the item crop for `GET /crops?item_text=` (`true` / `0.5`). Effective only when the profile names an OCR pipeline model |
| `OP_REGION_EMBED_ENABLED` | `true`: the worker writes a PE embedding per accepted or false-positive box at flush time (auto-disables if `pe_image_encoder` isn't ready) |
| `OP_REGION_MAX_BOXES_PER_WRITE` | `500`. Abuse guard on the number of boxes in one human region write request. Served as `region_profile.limits.max_boxes_per_write` |

The segmenter leg also needs a non-empty `segmenter_text_prompt`; without
one it is disabled even when `OP_SEGMENTER_URL` is set. How many boxes an
item may carry is the profile's `max_regions_per_item` (default `1`); see
[Multi-box regions](../guides/multi-box-regions.mdx).

To run a newly activated profile over items that already exist, use
`POST /curation/projects/{project}/reprocess` (see
[Reprocess](../operations/health-and-stalls.mdx#reprocessing)).

## Storage field-name overrides

`OP_REGION_FIELD_<ATTR>` (for example `OP_REGION_FIELD_STATUS`,
`OP_REGION_FIELD_BOXES`) maps a `RegionFields` attribute to a
different OpenSearch field, for data that already lives under other
names. A rename is a config flip, never a reindex, and the HTTP wire names
never change.

## VLM and segmenter

### VLM endpoints

`OP_VLM_URL` and `OP_VLM_MODEL` define the built-in, read-only `env` VLM
endpoint: the default a project runs until it activates another. More
endpoints (a remote vLLM, a hosted OpenAI-compatible API, a model served on
the host) are registered through `POST /curation/vlm/endpoints` and
activated per project; see [VLM selection](../guides/vlm-selection.mdx).
Keys are never put in `.env` or sent to the API: `openprocessor vlm key set <slug>`
writes `secrets/vlm/<slug>` and an endpoint references it as `secret:<slug>`.

| Variable | Default | Meaning |
|---|---|---|
| `OP_VLM_URL` | unset | OpenAI-compatible base, e.g. `http://vlm:8000/v1` (in-compose) or `http://host.docker.internal:<port>/v1` (a VLM on the host) |
| `OP_VLM_MODEL` | none | Required whenever `OP_VLM_URL` is set |
| `OP_VLM_API_KEY` | `EMPTY` | Key for the `env` endpoint |
| `OP_VLM_EXTERNAL_POLICY` | `ack` | Whether crops may be sent to an endpoint outside this deployment. `ack`: allowed once the operator acknowledges the warning when registering and activating it. `deny`: refused outright |
| `OP_VLM_SECRETS_DIR` | `/run/secrets/op_vlm` | Where `secret:<slug>` references resolve; a read-only mount of `./secrets/vlm` |
| `OP_LOCAL_VLM_ENDPOINT` | empty | Name of the registered endpoint that reaches the in-compose vLLM (the installer writes `env`). Empty means there is no in-compose VLM to switch |
| `OP_VLM_MAX_IMAGES_PER_CALL` | `8` | Per-request image cap for the `env` endpoint; **must equal the server's** `VLM_LIMIT_MM_IMAGES`. A registered endpoint carries its own `max_images_per_call` |
| `OP_VLM_OPEN_IMAGES_PER_CALL` | `3` | Open-vocabulary chunk size |
| `OP_VLM_HTTPX_MAX_CONNECTIONS` / `_KEEPALIVE` | `512` / `128` | |

:::tip[The most common VLM misconfiguration]
`OP_VLM_MAX_IMAGES_PER_CALL` (client) and `VLM_LIMIT_MM_IMAGES` (vLLM's
`--limit-mm-per-prompt`) are two ends of one contract. A request above the
smaller of the two is a `400`. Keep them numerically equal.
:::
