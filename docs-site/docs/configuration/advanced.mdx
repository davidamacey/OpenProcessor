# Configuration: advanced

Grouped by area, in the order `env.template` lists them. Every variable
is optional; defaults are shown where `env.template` states one.
`env.template`'s inline comments carry the full detail. Retired
vendor- or company-prefixed names are rejected loudly at startup (see
`src/config/retired_env.py`), as is the old `OP_DETECTION_*` prefix.

## OpenSearch indexes

| Variable | Default |
|---|---|
| `OP_IMAGES_INDEX` | `op_images` |
| `OP_ITEMS_INDEX` | `op_items` |
| `OP_LABELS_CONFIRMED_INDEX` | `op_labels_confirmed` |
| `OP_CLASSES_INDEX` | `op_classes` |
| `OP_CLUSTERS_INDEX` | `op_clusters` |

| `OP_UMAP_STATE_INDEX` / `OP_UMAP_VIZ_STATE_INDEX` | `op_umap_state` / `op_umap_viz_state` (two deliberately distinct indexes: the clustering reducer's cache and the visualization's run metadata) |

Indexes are created automatically at API startup; there is no manual
migration step.

## Ingest item detectors

`OP_INGEST_PRIMARY_<FIELD>` configures the required primary (an end2end,
already-NMS'd proposer); `OP_INGEST_SECONDARY_<FIELD>` an optional
raw-output detector whose IoU-matched hits override the primary's class.
Field names come from the `DetectionProfile` dataclass; tuple fields take
a comma-separated value.

| Variable | Example / default |
|---|---|
| `OP_INGEST_PRIMARY_DETECTOR_MODEL` | `yolov11_small_trt_end2end` (required) |
| `OP_INGEST_PRIMARY_INPUT_SIZE` | `640` |
| `OP_INGEST_PRIMARY_CONFIDENCE_FLOOR` | `0.4` |
| `OP_INGEST_PRIMARY_CLASS_IDS` | `2,3,5,7` (unset = all) |
| `OP_INGEST_PRIMARY_ASSIGNS_CLASS` | `false` |
| `OP_INGEST_PRIMARY_LABELS_PATH` | the proposer's `labels.txt`, recorded as each item's proposal name |
| `OP_INGEST_PRIMARY_NAME` | `item` |
| `OP_INGEST_PRIMARY_LETTERBOX_FILL` | `114,114,114` |
| `OP_INGEST_SECONDARY_DETECTOR_MODEL` | unset (off) |
| `OP_INGEST_SECONDARY_DETECTOR_VERSION` / `_INPUT_SIZE` / `_CONFIDENCE_FLOOR` / `_NAME` | `1` / `640` / `0.4` / `secondary` |

## Region detection profile

Off by default: with none of these set, no region profile is active,
`GET /curation/methods` advertises no detection profile, and the
detection worker idles. No profile ships built in.

| Variable | Meaning |
|---|---|
| `OP_REGION_PROFILE_PATH` | Load a profile JSON. This is a **container** path; compose mounts `./examples` at `/app/examples` read-only, and `examples/region_profiles/` holds a worked example |
| `OP_REGION_PROFILE` | Select a profile your own startup code registered by name (an unknown name fails at startup) |
| `OP_REGION_DETECTION_<FIELD>` | Per-field overrides, e.g. `_NAME`, `_DETECTOR_MODEL`, `_SEGMENTER_TEXT_PROMPT`, `_SECONDARY_SHAPE_GROUPS` |
| `OP_REGION_DETECTION_TEXT_READER` | `vlm`, `ocr`, `vlm_then_ocr` (default) or `both` |
| `OP_REGION_DETECTION_TEXT_*` | Dominant-text rules: `_MIN_HEIGHT_RATIO`, `_BORDER_MARGIN`, `_CHARSET`, `_STOPWORDS`, `_FORMAT`, `_PLACEHOLDERS`, `_REJECT_SEQUENCES` |
| `OP_ITEM_TEXT_ENABLED` / `OP_ITEM_TEXT_MIN_CONFIDENCE` | Store OCR lines read on the item crop for `GET /crops?item_text=` (`true` / `0.5`) |
| `OP_REGION_EMBED_ENABLED` | `true`: the worker writes region embeddings at flush time (auto-disables if `pe_image_encoder` isn't ready) |

The segmenter leg also needs a non-empty `SEGMENTER_TEXT_PROMPT` field;
without one it is disabled even when `OP_SEGMENTER_URL` is set.
Enabling a profile on a deployment that already has items: backfill them
once with `python3 scripts/curation/requeue_regions.py --missing-status`
(dry run) and then `--missing-status --apply`.

## Storage field-name overrides

`OP_REGION_FIELD_<ATTR>` (for example `OP_REGION_FIELD_STATUS`,
`OP_REGION_FIELD_BOXES`) maps a `RegionFields` attribute to a
different OpenSearch field, for data that already lives under other
names. A rename is a config flip, never a reindex, and the HTTP wire names
never change.

## GPU arbiter

| Variable | Meaning |
|---|---|
| `OP_GPU_ALLOWED_IDS` | GPU ids training/bake-off jobs may target; empty = any |
| `OP_GPU_ARBITER_CONTAINERS` | Containers stopped while a run holds GPUs and restarted after: `name` (only on multi-GPU claims) or `name@ids` with `/`-separated ids (e.g. `segmenter@0`) |
| `OP_GPU_ARBITER_TRAINER_CONTAINER` | Trainer probed by preflight; defaults to `<project>-trainer`. Empty string skips the probe |
| `OP_GPU_LABELS` | `id=label` pairs for `GET /train/gpus` |
| `OP_TRAIN_DEFAULT_GPUS` | Default `cuda_visible_devices` for new specs |
| `OP_BAKEOFF_HOST_GPUS` | Host GPU ids the evaluator uses, to scope which containers a bake-off stops |

Stopping containers needs the Docker socket, which only the
`docker-compose.gpu-arbiter.yml` overlay mounts. Without it, arbiter calls
are logged no-ops. See [Security](../deployment/security.mdx).

:::tip[The most common VLM misconfiguration]
`OP_VLM_MAX_IMAGES_PER_CALL` (client) and `VLM_LIMIT_MM_IMAGES` (vLLM's
`--limit-mm-per-prompt`) are two ends of one contract. A request above the
smaller of the two is a `400`. Keep them numerically equal.
:::
