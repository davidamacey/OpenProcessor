# Screenshots and image credits

OpenProcessor is a backend and has no UI of its own. Two kinds of
screenshots appear in these docs: the tools the stack ships (Swagger UI,
Prometheus, Grafana, MLflow, OpenSearch Dashboards; see
[Backend screenshots](#backend-screenshots)), and the curation screens,
which were **captured from Cropwright, a frontend for this backend**,
and are used here because they show backend-driven features directly:
cluster cards (`GET /curation/projects/{project}/clusters`), review queues
(`GET /curation/projects/{project}/review/{tab}`), region review, training
(the `train` routes) and model comparison (the `bakeoff` routes).

Screens for the project, config-store, VLM-selection and multi-box features
are not captured yet. Where a page needs one, it carries a placeholder of
the form `> Screenshot pending: Cropwright (<what it will show>)`. Replace
the placeholder with a `<Screenshot />` once the PNG exists.

**Public data only.** Every screenshot must come from an instance holding
public sample data (`make sample-coco`, `make sample-plates`). Never
capture from, or commit an image sourced from, a real deployment: its
imagery, class names and counts are not public data.

The files live under `docs-site/static/img/screenshots/`. The landing-page
showcase list is `docs-site/src/data/screenshots.json`, and the frontend
routes they were captured from are recorded in
`docs-site/src/data/screenshot_routes.json`. Cropwright's own capture
script drives a browser against those routes; review every PNG for
leaked hostnames, paths or unexpected text before committing it.

## Backend screenshots

The "See the backend in action" gallery on the landing page, and the
screenshots on [Monitoring](../operations/monitoring.mdx) and
[Training, bake-off and promote](../operations/training-and-promote.mdx),
are the tools the stack ships, captured by
`scripts/docs/capture_backend_screens.py` from a stack holding public
sample data only:

```bash
# 1. A few minutes of read-only inference traffic (COCO val2017 images),
#    so the dashboards have live data. Nothing is ingested or indexed.
.venv/bin/python scripts/docs/capture_backend_screens.py traffic \
  --api http://localhost:<api-port> --seconds 300

# 2. 1600-px screenshots of every tool.
.venv/bin/python scripts/docs/capture_backend_screens.py capture \
  --api http://localhost:<api-port> --prometheus http://localhost:<prometheus-port> \
  --grafana http://localhost:<grafana-port> --mlflow http://localhost:<mlflow-port> \
  --osd http://localhost:<dashboards-port> --out <dir>
```

It writes the model status (`GET /models/`, rendered as a terminal
frame), Swagger UI's endpoint groups, Prometheus target health, each
Grafana dashboard, MLflow's experiment, run, metric-chart and run
comparison pages, and OpenSearch Dashboards' index list. Grafana needs a
viewer login: the script reads `DOCS_GRAFANA_TOKEN` (a service-account
token) or `DOCS_GRAFANA_USER` and `DOCS_GRAFANA_PASSWORD` from the
environment, sends them only to Grafana, never prints them, and skips
Grafana when they are unset. The script refuses any URL on ports
4600-4799, which are reserved for non-public stacks. Copy the PNGs you
want into `docs-site/static/img/screenshots/` as `backend-<name>.png` and
list them in `docs-site/src/data/backend_screenshots.json`.

The screenshots show the user interfaces of
[Swagger UI](https://github.com/swagger-api/swagger-ui) (Apache-2.0),
[Prometheus](https://github.com/prometheus/prometheus) (Apache-2.0),
[Grafana](https://github.com/grafana/grafana) (AGPL-3.0),
[MLflow](https://github.com/mlflow/mlflow) (Apache-2.0) and
[OpenSearch Dashboards](https://github.com/opensearch-project/OpenSearch-Dashboards)
(Apache-2.0); product names belong to their respective owners. The data
in them (model
names, metrics, runs, index counts) comes from the public-sample-data
stack.

## The landing-page walkthrough GIF

`docs-site/static/img/openprocessor-workflow.gif` is built by
`scripts/docs/create-workflow-gif.sh` (ImageMagick) from frames captured
by `scripts/docs/capture_hero_frames.py` and
`scripts/docs/capture_backend_screens.py` against a running stack holding
public sample data:

```bash
OP_DOCS_API=http://localhost:<api-port> \
OP_DOCS_PROMETHEUS=http://localhost:<prometheus-port> \
OP_DOCS_GRAFANA=http://localhost:<grafana-port> \
OP_DOCS_MLFLOW=http://localhost:<mlflow-port> \
OP_DOCS_OSD=http://localhost:<dashboards-port> \
PYTHON=.venv/bin/python scripts/docs/create-workflow-gif.sh
```

The frames run in this order, each with a caption bar: a terminal session
(`/detect` on a public COCO image, `/embed/text`, the curation ingest
limits and status), Swagger UI, Triton model status, the Grafana
dashboards, Prometheus targets, MLflow runs and a run comparison,
OpenSearch Dashboards, and two closing frames from the Cropwright
screenshots above. Each tool's frames are skipped when its URL is unset
(Grafana's also without a login). Every request the capture makes is
read-only. Per-frame display times are the `DELAY` table at the top of
the script (dense UI frames 4-5 s, terminal frames under 2 s).
`KEEP_FRAMES=<dir>` keeps the captioned frames for review, and
`GIF_COLORS` (default 96) trades palette size against file size; keep the
GIF under about 1.5 MB. Set `heroDemo` to `null` in
`docs-site/site.config.ts` to hide it.

## Image credits

The screenshots show photographs from the [COCO](https://cocodataset.org)
2017 set and the
[Open Images](https://storage.googleapis.com/openimages/web/index.html) V7
"Vehicle registration plate" subset, fetched by the sample tooling above.
COCO images are Flickr uploads under their owners' Creative Commons
licenses (filtered to redistributable ones); Open Images images are listed
by their authors as CC BY 2.0. Per-image author and license records are in
the `ATTRIBUTION.csv` each fetch writes. Boxes, labels and scores shown are
produced by OpenProcessor and drawn by Cropwright, not by either dataset.

## Building these docs

```bash
cd docs-site
npm ci
npm run build          # fails on any broken link or anchor
npx docusaurus serve   # preview the production build
```

`docs-site/Dockerfile` builds the same site into an unprivileged nginx
image, and `.github/workflows/docs.yml` builds it on pull requests and
publishes it to GitHub Pages from the default branch.
