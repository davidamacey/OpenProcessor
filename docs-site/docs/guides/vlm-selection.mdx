# VLM selection

The vision-language model (VLM) that verifies regions, reads text and proposes labels is a
runtime choice. Endpoints are registered once for the deployment; each project activates
one. Any OpenAI-compatible `/v1/chat/completions` server with vision input works: a vLLM
container in the stack, a server on the host or LAN, or a hosted API.

Examples assume `API=http://localhost:4603` and project `cars`.

## Concepts

- **Endpoint:** a named, versioned record (`base_url`, `model`, request limits). The API
  key is never stored; the endpoint holds `api_key_ref`, a pointer.
- **Built-in `env` endpoint:** built from `OP_VLM_URL`, `OP_VLM_MODEL`, `OP_VLM_API_KEY`;
  read-only (clone it to edit). **A project calls no VLM until it activates one**, so
  `OP_VLM_URL` alone does nothing for a project. A run can still name an endpoint with
  `vlm=<name>` without changing the project.
- **Off:** the state of a new project (`active.name` null, `source` `off`). A VLM call that
  names no endpoint then answers `409 vlm_not_configured`.
- **Key references:** `secret:<slug>` names a file in `OP_VLM_SECRETS_DIR` (a read-only mount
  of `secrets/vlm`). `env:OP_VLM_API_KEY` is valid only on the built-in endpoint. Write a
  secret with `openprocessor vlm key set <slug>`, never through the API.
- **Locality:** the API classifies `base_url` as `compose`, `host`, `private`, `external` or
  `unknown` (unresolvable counts as external). External endpoints send crops to a third party.
- **External policy:** `OP_VLM_EXTERNAL_POLICY` is `ack` (default) or `deny`. With `ack`, an
  external endpoint needs `allow_external: true` when registered and
  `acknowledge_external: true` when activated. With `deny` it is refused.
- **URL policy:** this stack's own non-VLM services, link-local and cloud-metadata
  addresses are always refused; no flag bypasses this.
- **Probe:** a test call with synthetic images recording model listed, vision, JSON mode,
  multi-image limit and context length.
- **Catalog:** models the in-compose vLLM can serve, with VRAM and a `fits` flag
  (`examples/vlm/catalog.tsv`).

## Routes

Deployment-wide registry:

| Call | Purpose |
|---|---|
| `GET`/`POST /curation/vlm/endpoints` | List with usage and policy / register |
| `GET /curation/vlm/endpoints/schema` | Field specs for a form |
| `POST /curation/vlm/endpoints/validate` | Validate a draft without saving |
| `GET`/`PUT`/`DELETE /curation/vlm/endpoints/{name}` | Read with last probe / new revision / delete (refused while in use) |
| `POST /curation/vlm/endpoints/{name}/clone` | Copy to a new name |
| `POST /curation/vlm/endpoints/{name}/probe` | Probe and record |
| `GET /curation/vlm/endpoints/{name}/revisions[/{revision}]` | History |
| `GET /curation/vlm/catalog`, `GET /curation/vlm/local` | Catalog with `fits`, `serving`, `desired`; local status |
| `POST`/`DELETE /curation/vlm/local/select` | Record / clear the desired local model |

Per project: `GET /curation/projects/{project}/vlm/endpoints/active`,
`POST /curation/projects/{project}/vlm/endpoints/{name}/activate`,
`POST /curation/projects/{project}/vlm/endpoints/deactivate`,
`POST /curation/projects/{project}/vlm/endpoints/active/rollback`.

## Register an endpoint

`validate` never writes and always answers 200; `probe=true` also contacts the endpoint.

```bash
curl -s -X POST "$API/curation/vlm/endpoints/validate?probe=true" \
  -H 'Content-Type: application/json' \
  -d '{"body": {"base_url": "http://host.docker.internal:8012/v1",
        "model": "my-vision-model", "api_key_ref": "secret:my_server"}}'
```

The response has `validation` (`ok`, `errors`, `warnings`, `force_allowed`), `locality`,
`sends_images_externally` and `probe`.

| Body field | Default | Notes |
|---|---|---|
| `base_url` | required | http or https; no credentials, query or fragment |
| `model` | required | Model id the server expects |
| `api_key_ref` | null | `secret:<slug>` (1 to 64 of `a-z0-9_`) |
| `max_images_per_call` | 8 | 1 to 64; must not exceed the server's own limit |
| `open_images_per_call` | 3 | 1 to 64; chunk size for open-vocabulary labeling |
| `timeout_s` | 240 | 5 to 900 |
| `requests_per_second` | 500 | 0.1 to 10000 |
| `provider` | `vllm` | `vllm`, `ollama`, `anthropic`, `openai_compatible`; sets the defaults of the next two fields and the headers sent (see [Providers](#providers)) |
| `json_mode` | provider default | `auto`, `on`, `off`: send `response_format: json_object` |
| `temperature` | provider default | 0 to 2, or `null` to send none |
| `allow_external` | false | Required outside the deployment |
| `catalog_id` | null | Links to a catalog entry |

Names match `^[a-z0-9][a-z0-9_.-]{1,63}$`; `env`, `off`, `none`, `default`, `local`,
`active`, `schema`, `validate`, `deactivate` and names starting with `_` are reserved.

```bash
curl -s -X POST "$API/curation/vlm/endpoints" -H 'Content-Type: application/json' \
  -d '{"name": "host-vlm", "description": "vLLM on the host",
       "body": {"base_url": "http://host.docker.internal:8012/v1", "model": "my-vision-model"}}'
# new revision (changes nothing a project runs until re-activated)
curl -s -X PUT "$API/curation/vlm/endpoints/host-vlm" -H 'Content-Type: application/json' \
  -d '{"expected_revision": 1, "body": {"base_url": "http://host.docker.internal:8012/v1",
       "model": "my-vision-model", "max_images_per_call": 4}}'
curl -s -X POST "$API/curation/vlm/endpoints/env/clone" -H 'Content-Type: application/json' \
  -d '{"new_name": "env-copy"}'
curl -s -X DELETE "$API/curation/vlm/endpoints/host-vlm?expected_revision=2"
curl -s -X POST "$API/curation/vlm/endpoints/host-vlm/probe"
```

Register answers 201 with `body`, `revision`, `etag`, `locality`, `last_probe`,
`validation` and `active_in`. Cloning `env` drops its `env:OP_VLM_API_KEY` reference. A
probe returns `ok`, `latency_ms`, `model_listed`, `vision_ok`, `json_mode_supported`,
`max_images_ok`, `max_model_len`, `issues` and more; it does not change the revision, and
extra concurrent probes get 429 `probe_busy`.

## Activate for a project

```bash
curl -s -X POST "$API/curation/projects/cars/vlm/endpoints/host-vlm/activate" \
  -H 'Content-Type: application/json' \
  -d '{"revision": null, "acknowledge_external": false, "force": false, "expected_active": null}'
```

`revision` null means latest. `expected_active` (`{"name": ..., "revision": ...}`) makes
the call 409 if the active endpoint changed meanwhile. `force` bypasses only errors the gate
marks bypassable, such as an unprobed endpoint. Activation passes a gate that checks the VLM
against the active prompt pack and region profile. The response has `active`, `source`
(`stored`, `env`, `off`), `previous` (the rollback target), `activated_at`,
`config_revision`, `applied` (per worker, with `lagging`) and `validation`. Workers swap at
a quiet point, so `applied` can lag briefly.

```bash
curl -s "$API/curation/projects/cars/vlm/endpoints/active"
curl -s -X POST "$API/curation/projects/cars/vlm/endpoints/deactivate" \
  -H 'Content-Type: application/json' -d '{"expected_active": null}'
curl -s -X POST "$API/curation/projects/cars/vlm/endpoints/active/rollback" \
  -H 'Content-Type: application/json' -d '{"expected_active": null}'
```

`deactivate` stores the explicit off state: calls that need the project's VLM and name no
endpoint get 409 `vlm_not_configured`, and the VLM worker idles for that project. To keep
the VLM for explicit runs but stop the automated writers, set the VLM policy to
`scope: off` instead ([Scope and budget](#scope-and-budget); see
[Pipeline modes](./pipeline-modes.mdx)).

Labeling routes (`.../vlm/label_batch`, `.../pipeline/auto_label` and others) accept a
per-run `vlm` query parameter (`name` or `name@revision`) that overrides the project
default for that run only.

## Local models

When the stack runs its own vLLM container, the catalog lists what it can serve.

```bash
curl -s "$API/curation/vlm/catalog"
curl -s "$API/curation/vlm/local"
```

An entry has `id`, `hf_repo`, `license`, `gated`, `vram_gb`, `context_max`, `max_images`,
`status` (`tested` or `to_verify`), `fits`, `serving`, `desired`. The installer picks only a
`tested` entry that fits; a `to_verify` one (labelled "Unverified (experimental)") runs only
when named with `--vlm-model-id`. After choosing, run `openprocessor vlm probe` and read the
pairing warnings.

The API cannot restart containers. Selecting records the request and the host applies it:

```bash
curl -s -X POST "$API/curation/vlm/local/select" -H 'Content-Type: application/json' \
  -d '{"catalog_id": "<id from the catalog>", "force": false}'
```

The answer is 202 with `restart_required: true` and `desired.command`. Clear it with
`DELETE /curation/vlm/local/select`.

## CLI

Run `./openprocessor` in an installed directory, or `./scripts/openprocessor.sh` in a checkout.

| Command | Action |
|---|---|
| `vlm list` | Catalog: id, licence, VRAM, status |
| `vlm status` | Model in `.env`, endpoint, what is served and desired |
| `vlm use <id> [--force] [--yes]` | Switch the in-compose VLM to a catalog entry |
| `vlm apply [--force] [--yes]` | Apply the model requested through the API |
| `vlm probe` | Probe the endpoint in `OP_LOCAL_VLM_ENDPOINT` |
| `vlm key set <slug>` | Read a key from the terminal into `secrets/vlm/<slug>` (mode 600) |

`vlm use` checks the model fits the GPU (`--force` overrides), that a gated model's Hugging
Face token can see it, and that no training run holds the GPUs. It pauses the workers,
rewrites `.env` after a backup, recreates the vlm container, waits for the new model,
probes, clears the request and unpauses; on failure it restores the previous `.env` and
container. `vlm use` and `vlm probe` need `OP_LOCAL_VLM_ENDPOINT`.

**Enable the in-compose VLM on an existing install** (no `vlm` tier yet): re-run
`./setup-openprocessor.sh --tiers core,curation,vlm` (your tiers plus `vlm`), which picks a
model that fits and writes `VLM_CATALOG_ID`, `VLM_MODEL`, `OP_VLM_URL` and
`OP_LOCAL_VLM_ENDPOINT=env`. Or set `OP_LOCAL_VLM_ENDPOINT=env` by hand, keep `vlm` in
`COMPOSE_PROFILES`, run `docker compose --profile vlm up -d vlm`, then
`openprocessor vlm use <id>`.

## Errors

| Status | `error` | When |
|---|---|---|
| 404 | `not_found`, `unknown_revision` | Unknown endpoint or revision |
| 403 | `read_only` | Edit or delete of `env` |
| 409 | `name_conflict`, `revision_conflict` | Name used; stale `expected_revision` |
| 409 | `in_use` | Delete while a project runs it (`projects` lists them) |
| 409 | `active_conflict` | Another writer activated first (`current` returned) |
| 409 | `no_previous`, `previous_deleted` | Nothing to roll back to |
| 409 | `no_local_vlm` | Local select without an in-compose VLM |
| 422 | `validation_failed` | Blocking errors; `report` lists them |
| 422 | `vlm_external_not_acknowledged` | External endpoint not acknowledged |
| 422 | `unknown_catalog_id`, `vlm_catalog_does_not_fit` | Not in catalog; needs more VRAM than the card has |
| 429 | `probe_busy` | Too many probes |

Validation issue codes start with `vlm_` (for example `vlm_url_denied_internal_service`,
`vlm_unreachable`, `vlm_auth_failed`, `vlm_model_not_listed`, `vlm_no_vision`,
`vlm_json_mode_unsupported`, `vlm_max_images_exceeds_server`, `vlm_not_probed`,
`vlm_context_too_small`).

## Providers

`provider` is explicit, not guessed from the host. It sets the defaults for `json_mode` and
`temperature` (override either per endpoint) and the headers the probe and every call send.

| Provider | `json_mode` | `temperature` | Notes |
|---|---|---|---|
| `vllm` (default) | `auto` | `0.0` | Unchanged from earlier releases |
| `ollama` | `auto` | `0.0` | Images go as base64 data URLs, which is what the labeler sends |
| `openai_compatible` | `auto` | `0.0` | Any other server that follows the OpenAI chat API |
| `anthropic` | `off` | none | Adds `anthropic-version: 2023-06-01` |

The probe sends a minimal chat call with the endpoint's own parameters, so a rejected
parameter shows up as `vlm_http_error` with the provider's message.

**vLLM** (the `vlm` service or your own server). Sources: vLLM "OpenAI-Compatible Server" docs.

```bash
curl -s -X POST "$API/curation/vlm/endpoints" -H 'Content-Type: application/json' \
  -d '{"name": "host-vllm", "body": {"provider": "vllm",
       "base_url": "http://host.docker.internal:8012/v1", "model": "my-vision-model"}}'
```

**Ollama** (host or LAN, port 11434). Sources: Ollama "OpenAI compatibility" docs: `/v1/models`,
`response_format`, `temperature` and base64 images are supported; the API key is ignored, so
register without `api_key_ref`. Pull the model first (`ollama pull <model>`).

```bash
curl -s -X POST "$API/curation/vlm/endpoints" -H 'Content-Type: application/json' \
  -d '{"name": "ollama-vision", "body": {"provider": "ollama",
       "base_url": "http://host.docker.internal:11434/v1", "model": "<a vision model you pulled>"}}'
```

**Anthropic** (cloud). Sources: Anthropic "OpenAI SDK compatibility" docs: `json_object` is
rejected with 400, `temperature` below 1 is rejected on current models, and `/models` needs the
`anthropic-version` header. Crops leave your deployment, so `allow_external` is required.
Write the key with `openprocessor vlm key set anthropic`, never inline.

```bash
curl -s -X POST "$API/curation/vlm/endpoints" -H 'Content-Type: application/json' \
  -d '{"name": "claude", "body": {"provider": "anthropic",
       "base_url": "https://api.anthropic.com/v1", "model": "claude-haiku-5-5",
       "api_key_ref": "secret:anthropic", "allow_external": true}}'
```

The same settings for the built-in endpoint: `OP_VLM_PROVIDER`, `OP_VLM_JSON_MODE` and
`OP_VLM_TEMPERATURE` (`none` sends no temperature); see
[advanced configuration](../configuration/advanced.mdx).

## Failed label batches

A provider answering HTTP 4xx (a rejected parameter, a bad key, an unknown model) is a
configuration error: `vlm_label_batch` and `vlm_verify_region_batch` end `failed` with
`error_code` `vlm_request_rejected` and a message naming the endpoint, the status and the
provider's text. It is never retried and never `completed`. A 5xx, a timeout or no connection
stays `vlm_unreachable` (`result.vlm_unreachable`).

## Scope and budget

Two automated writers label crops: `curation-vlm-worker` and the `auto_label` VLM stage
(`run_vlm=true`). By default both label every eligible crop, a long and, on a hosted
endpoint, paid run on a large project. A per-project policy limits them. VLM labels stay
unvalidated suggestions (`class_source: "vlm"`), excluded from export and the test holdout
until a human validates them.

```bash
curl -s "$API/curation/projects/cars/vlm/policy"
curl -s -X PUT "$API/curation/projects/cars/vlm/policy" -H 'Content-Type: application/json' \
  -d '{"expected_revision": 0, "scope": "representatives", "per_cluster": 5,
       "max_crops_per_day": 2000}'
```

| Field | Default | Notes |
|---|---|---|
| `scope` | `all` | `all`, `uncertain`, `representatives`, `off` |
| `conf_max` | 0.80 | `uncertain` only: detector confidence below this, or none recorded |
| `per_cluster` | 5 | `representatives` only (1 to 100): crops nearest each cluster centre; every unassigned crop is also kept |
| `max_crops_per_day` | 0 | VLM class attempts per UTC day; 0 is unlimited |
| `region_verify` | `vlm` | `vlm` or `none` (boxes accepted without a VLM); a per-item `region_run_verify` from an assist `segment` run wins |
| `sample_frac` | 1.0 | Above 0 up to 1; a stable hash-chosen fraction of crop ids |

`off` stops both automated writers. The write needs the `expected_revision` you read (409
`revision_conflict` when stale). The worker re-reads the policy about every 30 seconds; the
next `auto_label` run uses it at once and can override with `vlm_scope=<scope>`. The policy
is cloned with the project.

An explicit request is never limited by the policy: an assist run over a cluster or named
crops, an `auto_label` run with `cluster_uid`, and labelling named crops. A human-validated
crop is never selected under any scope. When a policy leaves nothing to label, the VLM stage
reports why (`skipped` with the reason).

## Assist runs

`POST /curation/projects/{project}/assist/runs` sends a crop, selection, cluster or filter to
the VLM, optionally as a seeded representative sample, with `vlm=<name>` and `prompt_pack`
for that run. It is a dry run by default, needs an active endpoint or a `vlm` name, and
ignores the policy and daily budget. See [Selective VLM and segmenter assist](./selective-assist.mdx).
