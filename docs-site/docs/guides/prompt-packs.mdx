# Prompt packs

A prompt pack holds every instruction the VLM receives: how to classify an item, how to
verify a region, how to answer. The text is data, not code. Packs are editable per project,
versioned and revertible.

Examples assume `API=http://localhost:4603`, project `cars` and a base of
`$API/curation/projects/cars/prompt_packs`.

## Concepts

- **Fields.** Text fields come in system and user pairs, one pair per VLM call:

  | Call | Fields |
  |---|---|
  | `classify` | `class_system`, `class_user_template` |
  | `open_classify` | `open_class_system`, `open_class_user_template` |
  | `combined` | `combined_system`, `combined_user_template` |
  | `combined_batch` | `combined_batch_system`, `combined_batch_rules` |
  | `region_verify` | `region_system`, `region_user` |
  | `region_verify_batch` | `region_batch_system`, `region_batch_user` |
  | `region_visible` | `region_visible_system`, `region_visible_user` |

  Two maps: `class_descriptions` (class name to a short description) and `synonyms` (a label
  the model may answer, mapped to the registry class it stands for).
  `proposal_denylist` is an optional list of case-insensitive globs (`blurry_*`, `*_scene`)
  for proposed new-class names that are scene or quality words; a match drops the proposal.
  `detector_hint_min_confidence_pct` (0 = off, max 100) adds one line per image naming the
  item's stored detector class when its confidence is at least that percent; it is a hint,
  not a constraint, and was measured on a COCO-trained detector against COCO ground truth,
  so the gain may be optimistic for other domains.
- **Attributes.** A pack may declare up to 16 `attributes`: facts a VLM reports about an
  item or box (a car's make, a wheel's rim material). Each has a `key`
  (`^[a-z][a-z0-9_]{0,31}$`, unique), a `description` (300 characters), optional closed
  `values` (up to 50, lowercase, 48 characters) and `applies_to` (`item` default, or `box`).
  Two more calls report them; their fields stay empty while no attributes are declared:

  | Call | Fields | Used for |
  |---|---|---|
  | `assist` | `assist_system`, `assist_user_template` | Classify and report item attributes in one call |
  | `attributes` | `attributes_system`, `attributes_user_template` | Attributes alone: items without classify, box sub-crops |

  The server renders `{attribute_block}` from `attributes`. Replies carry
  `{key: {"value": ..., "confidence": "high"|"medium"|"low"}}`; undeclared keys and values
  outside a closed vocabulary are dropped. An attribute is a suggestion: it never changes a
  class or box. Item attributes need all four prompt fields; box attributes the
  `attributes_*` pair. `examples/prompt_packs/vehicle_wheel.json` declares `make`, `model`,
  `body_style` and `rim_material`. The region worker and `auto_label/start?vlm_attributes=true`
  store them in the item's `assist` slot. Preview on up to 64 crops with
  `POST .../prompt_packs/test` and `call: "assist"` or `"attributes"`.
- **Placeholders.** Only some fields are formatted with `str.format`: `class_user_template`
  and `open_class_user_template` take `class_names_csv`; `combined_user_template` takes
  `class_block` and `region_block`; `assist_user_template` takes `{class_list}` and
  `{attribute_block}` (may use `{n_images}`); `attributes_user_template` takes
  `{attribute_block}`. Each must use all its required placeholders and no others; a literal
  brace is doubled. Every other field is sent verbatim and a placeholder in it is an error.
- **Reply keys.** The worker parses the model's JSON reply, so the text must name the keys
  the call needs (for example `is_region` and `confidence` for `region_verify`).
  `GET .../prompt_packs/schema` lists them per field.
- **Sources.** `builtin` (shipped generic packs, with a starter `proposal_denylist`), `file`
  (`OP_PROMPT_PACK_PATH` / `OP_PROMPT_PACK_PATHS`, comma separated), `template`
  (`examples/prompt_packs/`) and `stored` (saved in the project). Only `stored` packs are
  editable; clone the others.
- **Revisions and activation.** Every save is a new numbered revision. One pack is active per
  project; activation passes a gate that pairs it with the active region profile and VLM. A
  change takes effect only when activated.

## Routes

Under `/curation/projects/{project}/prompt_packs`:

| Call | Purpose |
|---|---|
| `GET`, `POST` | List packs, templates and the active one / create a stored pack |
| `GET /curation/projects/{project}/prompt_packs/schema` | Field, call and placeholder specs |
| `POST /curation/projects/{project}/prompt_packs/validate` | Validate a draft; never writes |
| `POST /curation/projects/{project}/prompt_packs/test` | Dry run against crops ([Test on a crop](./test-on-crop.mdx)) |
| `GET /curation/projects/{project}/prompt_packs/active`, `POST /curation/projects/{project}/prompt_packs/active/rollback` | Active pack and what workers applied / re-activate the previous |
| `GET`, `PUT`, `DELETE /curation/projects/{project}/prompt_packs/{name}` | One pack / new revision / delete a stored pack |
| `POST /curation/projects/{project}/prompt_packs/{name}/activate`, `POST /curation/projects/{project}/prompt_packs/{name}/clone` | Activate / copy into a new stored pack |
| `GET /curation/projects/{project}/prompt_packs/{name}/revisions[/{revision}]` | History |

```bash
curl -s "$API/curation/projects/cars/prompt_packs"
curl -s "$API/curation/projects/cars/prompt_packs/schema"
curl -s "$API/curation/projects/cars/prompt_packs/vehicle_wheel"
```

The list has `packs` (`name`, `source`, `read_only`, `revision`, `active`,
`asks_region_text`, `etag`), `templates`, `active` and `config_revision`. A pack document
has `body`, `description`, `revision`, `cloned_from`, `etag` and, after a write, `validation`.

## Validate

```bash
curl -s -X POST "$API/curation/projects/cars/prompt_packs/validate?profile=vehicle_wheel" \
  -H 'Content-Type: application/json' \
  -d '{"name": "cars_v1", "body": {"region_system": "You verify a wheel.", "region_user": "Reply as JSON with is_region and confidence."}}'
```

The body may be partial; missing content is reported as issues, not an HTTP error. `profile`
pairs the pack with a named region profile (default the active one). The response is
`{ok, errors, warnings, force_allowed}`; each issue has `code`, `severity`, `field`,
`message`, `detail`.

| Code | Severity | Meaning |
|---|---|---|
| `pack_name_invalid`, `pack_name_reserved`, `name_conflict` | error | Name must match `^[a-z0-9][a-z0-9_.-]{1,63}$`; `off`, `none`, `default` reserved; name used |
| `pack_field_missing`, `pack_field_empty`, `pack_field_too_long`, `pack_field_out_of_range` | error | Field absent, blank, over 20000 characters (or too many attributes or entries), or hint percent outside 0 to 100 |
| `pack_template_format_error` | error | Field cannot be formatted (a single brace) |
| `pack_placeholder_missing`, `pack_placeholder_unknown`, `pack_placeholder_in_verbatim_field` | error | Placeholder problems |
| `pack_reply_key_missing` | error | Text does not name a required reply key |
| `pack_attribute_invalid`, `pack_attribute_duplicate` | error | Bad attribute entry; shared key |
| `pack_multi_region_keys_missing` | warning on validate, error on activation | The profile allows more than one box per item and the combined prompts lack the per-box keys |
| `pack_asks_text_profile_text_free`, `pack_no_text_profile_reads_text` | warning | Pack and profile disagree about reading text |
| `pack_synonym_target_unknown`, `pack_description_class_unknown` | warning | A map names a class not in the registry |
| `pack_example_values` | info | Quoted example values the model may echo back |

## Create, edit, clone

Clone a template or built-in pack to start. `source` (`builtin`, `file`, `template`,
`stored`) picks the copy when a name exists in several places; `revision` picks a stored
revision; `from_project` clones from another project. Answers 201.

```bash
curl -s -X POST "$API/curation/projects/cars/prompt_packs/vehicle_wheel/clone" \
  -H 'Content-Type: application/json' \
  -d '{"new_name": "cars_v1", "description": "My wheel prompts", "source": "template"}'

curl -s -X PUT "$API/curation/projects/cars/prompt_packs/cars_v1" \
  -H 'Content-Type: application/json' \
  -d '{"expected_revision": 1, "description": "tighter wording", "body": { ...all fields... }}'
```

`POST .../prompt_packs` creates from scratch with every text field set (see
`examples/prompt_packs/vehicle_wheel.json`). Create and save refuse validation errors with
422; warnings do not block. `expected_revision` is the revision you read.

## Activate, roll back, delete

```bash
curl -s -X POST "$API/curation/projects/cars/prompt_packs/cars_v1/activate" \
  -H 'Content-Type: application/json' \
  -d '{"revision": null, "force": false, "expected_active": null}'
curl -s -X POST "$API/curation/projects/cars/prompt_packs/active/rollback" \
  -H 'Content-Type: application/json' -d '{"expected_active": null}'
curl -s -X DELETE "$API/curation/projects/cars/prompt_packs/cars_v1?expected_revision=2"
```

`revision` null activates the latest. `expected_active` (`{name, revision}`) makes the call
409 if another writer activated first. `force` bypasses no pack error. Activation re-runs
the pairing checks with the active region profile and VLM (422 `validation_failed` with the
report on failure). The response has `active`, `previous`, `source`, `activated_at`,
`applied` (per worker, with `lagging`) and `validation`. Delete answers 204.

## Errors

| Status | `error` | When |
|---|---|---|
| 404 | `not_found`, `unknown_revision` | Unknown pack, source or revision |
| 403 | `read_only` | Save or delete of a built-in, file or template pack |
| 409 | `name_conflict`, `revision_conflict` | Name used; stale `expected_revision` (`current_revision` returned) |
| 409 | `in_use` | Delete of the active pack |
| 409 | `active_conflict` | Another writer changed the activation (`current` returned) |
| 409 | `no_previous`, `previous_deleted` | Nothing to roll back to |
| 422 | `validation_failed` | Validation errors (`report` lists them) |
