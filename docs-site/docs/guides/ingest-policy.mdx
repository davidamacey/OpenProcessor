# Ingest policy, filter and select

Each project has an ingest policy: which detections an ingest keeps, which get an embedding
vector, and whether clustering runs on its own. Set it **before** a large ingest
([Ingest a large folder](./ingest-large-folder.mdx)); it applies to future ingests and
explicit embed runs only and never rewrites what is stored. A project with no saved policy
stores and embeds every detection.

## Read, try and save

```bash
B=http://localhost:4603/curation/projects/<slug>/ingest/policy
curl -s $B                                  # current policy and its revision
curl -s -X POST $B/preview -H 'content-type: application/json' \
  -d '{"embedding": {"mode": "selected", "classes": ["person"]}}'
curl -s -X PUT $B -H 'content-type: application/json' \
  -d '{"expected_revision": 0, "embedding": {"mode": "lazy"}}'
```

- `GET` returns the policy and its `revision` (0 until the first save).
- `POST .../preview` is read-only: it runs the policy over stored items and answers
  `would_embed`, `would_not_embed`, `embedded_because_labeled`, `by_class` and
  `estimated_vector_mb` (raw 1,024-float vectors only, no index overhead). It returns zeros on
  an empty project, so preview after a trial run.
- `PUT` replaces the whole policy and needs the `expected_revision` you read (409
  `revision_conflict` when stale). Class names matching no detector label or registry class
  are saved and listed in `unknown_names`.

## Fields

**`detect`** filters detector output; a filtered detection is not stored. Empty by default
(keep everything); criteria combine with AND.

| Field | Meaning |
|---|---|
| `classes` | Keep only these detector class names (OR, matched by name) |
| `exclude_classes` | Drop these class names |
| `min_confidence` | 0 to 1 |
| `min_box_area_frac` | 0 to 1, box area as a fraction of the image |
| `max_per_image` | Keep the N best detections per image (at least 1) |
| `class_resolution` | `by_name` (default): a detection gets the class named like its detector label, and the class is added to the registry when it is missing; the label is a machine one (`class_source` `detector`), reviewable and still clustered. `proposal`: detections stay unlabeled proposals |

**`embedding.mode`** decides which stored detections get a vector:

| Mode | Behavior |
|---|---|
| `all` (default) | Every stored detection is embedded |
| `selected` | Only detections meeting the `embedding` criteria (`classes`, `min_confidence`, `min_box_area_frac`, `max_per_image`; at least one required). The rest are `not_selected` |
| `lazy` | None embedded at ingest; stored as `deferred`. The whole-frame vector is still stored |
| `none` | Detection only: nothing embedded and no whole-frame vector; the image encoder does not run at ingest. Stored as `deferred` |

An item with a human or imported label always gets a vector, whatever the mode.

**`clustering.automatic`** (default `true`). `false` means ingest and the `embed` scope place
no newly embedded item into a cluster, and the cluster refresh tick skips the project.
Clustering you ask for (`POST .../clusters/runs`, an auto-label job) always runs. With
`embedding.mode=none` and `clustering.automatic=false` the project is detection only
([Pipeline modes](./pipeline-modes.mdx#a-detection-only)):

```bash
curl -s -X PUT $B -H 'content-type: application/json' \
  -d '{"expected_revision": 0, "embedding": {"mode": "none"}, "clustering": {"automatic": false}}'
```

The policy does not choose the detector: a project's detector is its active
[ingest profile](./ingest-profiles.mdx). A stored `detector` field from an older version is
reset (logged as `retired_policy_field_reset`) the first time the policy is read. The retired
`OP_INGEST_PRIMARY_CLASS_IDS` setting is ignored; use the `detect` filter.

## Cost of a choice

Vectors dominate index size, so the mode is the main lever; sizes are in
[Ingest a large folder](./ingest-large-folder.mdx#6-time-and-disk) and the preview gives the
number for your data. Anything left without a vector can be embedded later with the `embed`
scope of [Reprocess](./reprocess.mdx) or the `embed_missing` stage of auto-label; until then
it is excluded from clustering, similarity search and the VLM.

## Filter, select, act

The same filter parameters work on the crop list, review queues, search, stats, clusters,
regions and `GET .../detections/summary`. Bulk actions (exclude, label, move, reprocess,
export) accept explicit ids or a `selection` (the filter plus `limit`, `sample`, `seed`), and
each supports `dry_run` so you see the count first.
