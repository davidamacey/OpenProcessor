# Keymaps

Every project has its own keyboard shortcut map for the review UI. The backend holds the
action registry, validates changes and stores overrides; a frontend such as Cropwright binds
keys from it. Examples assume `API=http://localhost:4603` and project `cars`.

## Concepts

- **Action.** One bindable operation with an id such as `review.queue.confirm`, a `context`,
  a `default` list of combos, a `modifiable` flag and `available` (false when it cannot apply
  yet, e.g. per-box region actions on a project with no region profile).
- **Context.** Where an action is live: `global`, `review`, `review.queue`, `review.region`,
  `box_edit`, `cluster`, `clusters_search`, `region_gallery`. A context includes others, so a
  key bound in `global` collides with the same key in any context that includes it.
- **Combo.** A key with optional modifiers (`ctrl`, `meta`, `alt`, `shift`), e.g.
  `shift+enter`. At most 3 per action.
- **Overrides.** Only differences from the default are stored; a project with no document
  serves the defaults (`is_default` true).
- **Locked.** `escape`, `enter` and the four arrow keys are locked; actions with
  `modifiable: false` (such as closing the overlay) cannot be rebound.
- **Class hotkeys.** A class may carry a single-letter `hotkey_letter`; a bare-letter combo
  cannot reuse one in a context where class hotkeys are live.
- **Revision.** Each write bumps `revision` and must name the revision it was based on.

## Routes

Under `/curation/projects/{project}/keymap`:

| Call | Purpose |
|---|---|
| `GET` | Registry, effective keys and stored overrides |
| `PUT` | Replace the whole override map |
| `POST /validate` | Dry run, always 200 |
| `POST /reset` | Drop all overrides, or only listed actions |

## Read and validate

```bash
curl -s "$API/curation/projects/cars/keymap"
```

The response has `actions` (`id`, `context`, `group`, `label`, `description`, `default`,
`keys` effective, `locked_keys`, `modifiable`, `available`), `contexts` (`id`, `label`,
`includes`, `class_hotkeys_live`), `grammar`, `overrides` (action id to combos),
`reserved_hotkeys`, `revision`, `etag` (`keymap:<revision>`), `is_default` and `issues`.

`validate` has the same replace semantics as `PUT`: the body is the whole proposed map, and a
body that validates clean also passes the real write.

```bash
curl -s -X POST "$API/curation/projects/cars/keymap/validate" \
  -H 'Content-Type: application/json' \
  -d '{"overrides": {"review.queue.discard": ["x"], "review.skip": ["s"]}}'
```

It returns `ok`, `errors`, `warnings`, `force_allowed`, `resolved`, `reserved_hotkeys` and
`class_conflicts`; each issue has `code`, `severity`, `field`, `message`, `detail`.

| Code | Meaning |
|---|---|
| `keymap_unknown_action`, `keymap_action_locked` | Unknown action id; action not modifiable |
| `keymap_combo_invalid`, `keymap_too_many_combos` | Malformed or repeated combo; more than 3 |
| `keymap_key_locked`, `keymap_browser_reserved`, `keymap_focus_key` | Locked key used elsewhere or removed from its owner; a browser-kept combo such as `ctrl+w`; a combo shadowing focus navigation outside box editing |
| `keymap_context_collision` | Same combo bound twice in one context |
| `keymap_overlay_unbound` | The shortcuts overlay must keep one key |
| `keymap_context_no_confirm` | Warning: a context has no confirm key |
| `keymap_class_hotkey_shadowed`, `keymap_class_hotkey_conflict` | A class letter shared with an action; a combo bound to a class in this project |

## Write and reset

`PUT` replaces the override map; an action missing from the body returns to its default. The
revision comes from `expected_revision` in the body or an `If-Match: "keymap:<revision>"`
header (if both, they must agree).

```bash
curl -s -X PUT "$API/curation/projects/cars/keymap" -H 'Content-Type: application/json' \
  -d '{"expected_revision": 0, "overrides": {"review.queue.discard": ["x"]},
       "unbind_conflicting_class_hotkeys": false}'
# reset all, or only some actions (action_ids omitted or null = all)
curl -s -X POST "$API/curation/projects/cars/keymap/reset" -H 'Content-Type: application/json' \
  -d '{"expected_revision": 2, "action_ids": ["review.queue.discard"]}'
```

The response matches `GET` plus `unbound_class_hotkeys`. A combo that clashes with a class
hotkey is refused with 409 `class_hotkey_conflict` and `class_conflicts`; set
`unbind_conflicting_class_hotkeys` to true to clear those hotkeys in the same write (they are
reported back, never cleared silently).

| Status | `error` | When |
|---|---|---|
| 422 | `validation_failed` | Validation errors (`report`), missing revision, malformed `If-Match`, or body and header disagree |
| 409 | `revision_conflict` | Stored revision differs (`current_revision` returned) |
| 409 | `class_hotkey_conflict`, `project_archived` | Combo collides with a class hotkey and unbinding was not requested; archived project |
| 404 | `project_not_found` | Unknown project |

## Cloning

`clone_settings` with the `keymap` axis copies the overrides. If any combo collides with a
class hotkey in the target, the whole keymap is skipped and each collision is listed in
`keymap_clone_conflicts`. See [Settings and configuration](./settings-and-config.mdx).
