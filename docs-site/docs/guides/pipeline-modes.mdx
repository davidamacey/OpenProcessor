# Pipeline modes

There is no mode switch. What runs is set by the compose services that are up, the
project's ingest policy, its VLM activation and VLM policy, and
`OP_CLUSTER_REFRESH_INTERVAL_S`. Examples assume `API=http://localhost:4603` and project
`cars`.

| Mode | What runs | How you select it |
|---|---|---|
| [(a) Detection only](#a-detection-only) | Core stack; ingest stores boxes | Ingest policy `embedding.mode=none`, `clustering.automatic=false` |
| [(b) Detection, embedding, clustering](#b-detection-embedding-and-clustering) | Core stack plus `curation` workers | The default |
| [(c) VLM-assisted labeling](#c-vlm-assisted-labeling-of-a-large-batch) | Mode (b) plus a VLM | VLM endpoint activation and VLM policy |
| [Selective VLM](#recipe-cluster-name-by-hand-then-run-the-vlm-for-one-thing) | Mode (b), VLM for one cluster or filter | The recipe below |
| [(d) Cluster-sampled loop](#d-iterative-cluster-sampled-auto-labeling) | Mode (b), a VLM, `curation-assist-loop-worker` | `POST .../assist/loops`; see [Auto-label loop](./auto-label-loop.mdx) |

## The knobs

| Knob | Where | Effect |
|---|---|---|
| Compose profiles | `COMPOSE_PROFILES` or `--profile` | Which services exist. See [Compose profiles](../getting-started/compose-profiles.mdx). |
| GPU profile | `./openprocessor profile` | Triton instance counts and batch sizes only. See [GPU sizing](../deployment/gpu-sizing.mdx#gpu-profiles). |
| Ingest policy | `GET`/`PUT .../ingest/policy` | What is stored, `embedding.mode` (`all`, `selected`, `lazy`, `none`), `clustering.automatic`. See [Ingest policy](./ingest-policy.mdx). |
| VLM activation | `POST .../vlm/endpoints/{name}/activate`, `.../vlm/endpoints/deactivate` | Which VLM a project calls. A new project has none. |
| VLM policy | `GET`/`PUT .../vlm/policy` | `scope` (`all`, `uncertain`, `representatives`, `off`), `per_cluster`, `max_crops_per_day`, `sample_frac`. See [VLM selection](./vlm-selection.mdx#scope-and-budget). |
| Region profile, prompt pack | config store | What the detection worker's cascade does per item. See [Region profiles](./region-profiles.mdx). |
| `OP_CLUSTER_REFRESH_INTERVAL_S` | `.env`, read by `jobs-beat` | Refresh tick interval (default 120; `0` removes it). |
| Cluster profile | `GET`/`PUT .../cluster_profiles/{name}` | Method, parameters, the `refresh` rule and whether a partition is served at once. |
| `OP_REGION_EMBED_ENABLED` | `.env` | `false` skips per-box region embeddings. |
| VLM CLI | `./openprocessor vlm list\|status\|use\|apply\|probe\|key set` | Switch the in-compose VLM model. |

## (a) Detection only

Boxes and classes from the detector, stored in a project, with no embedding or
clustering work. No worker is needed and no VLM runs.

**Stateless, nothing stored.** Needs only Triton and the API:

```bash
curl -s -X POST $API/detect -F "image=@000000000139.jpg"
```

`POST /detect/batch` takes up to 64 images.

**Stored, no vectors, no clustering.** Set the policy before you ingest. `none` stores
every detection as `deferred` with no vector, the whole-frame vector included:

```bash
curl -s -X PUT $API/curation/projects/cars/ingest/policy \
  -H 'content-type: application/json' \
  -d '{"expected_revision": 0, "embedding": {"mode": "none"},
       "clustering": {"automatic": false}}'
```

Then ingest ([Ingest a large folder](./ingest-large-folder.mdx)). Items with a human or
imported label still get a vector.

**Embed and cluster later.** One auto-label job does both; `embed_missing` embeds the
deferred items first, and an explicit job ignores `clustering.automatic`:

```bash
curl -s -X POST "$API/curation/projects/cars/pipeline/auto_label/start?embed_missing=true&train_clusters=true"
```

The `embed` scope of [Reprocess](./reprocess.mdx) embeds without clustering. A policy
change never rewrites stored items.

Start a subset of workers by name:

```bash
./openprocessor curation up curation-detection-worker
make curation-up SERVICES="curation-detection-worker curation-auto-label-worker"
```

`curation up` with no names starts the curation workers. `curation-evaluator` has its own
`evaluator` profile and starts only when named. `curation-detection-worker` runs the region
cascade and idles without a region profile.

## (b) Detection, embedding and clustering

The default once the `curation` profile is up: every detection is embedded
(`embedding.mode=all`) and clustering refreshes on its own.

```bash
./openprocessor curation up
./openprocessor curation status
```

**The VLM is off until you activate one.** `OP_VLM_URL` only defines the `env` endpoint a
project may opt into; `curation-vlm-worker` and the auto-label VLM stage skip a project
without an active endpoint.

```bash
curl -s $API/curation/projects/cars/vlm/endpoints/active   # "source":"off" on a new project
# switch off again (VLM calls that name no endpoint then answer 409 vlm_not_configured):
curl -s -X POST $API/curation/projects/cars/vlm/endpoints/deactivate \
  -H 'content-type: application/json' -d '{"expected_active": {"name": "env", "revision": null}}'
# keep the VLM active but stop the two automated writers (explicit requests still work):
curl -s -X PUT $API/curation/projects/cars/vlm/policy \
  -H 'content-type: application/json' -d '{"expected_revision": 0, "scope": "off"}'
```

**Cluster refresh.** Every `OP_CLUSTER_REFRESH_INTERVAL_S` seconds `jobs-beat` queues
`op.periodic.cluster_refresh`. For each active project it reads the active item cluster
profile's `refresh` rule and queues a `cluster_run` (on the `cluster` queue) when the
project grew by `growth_threshold` items (default 200). It waits for ingest to go quiet
(up to `max_deferral_s`, 1800), retries a failed run after `retry_backoff_s` (600), holds
while an auto-label loop is live, and queues nothing unless a `cluster-worker` reported in
within the last minute. The run writes a new partition; the profile's `activation`
(`human` by default) decides whether it is served at once or after you review it and
`PUT .../clusters/activation`. Change the rule by saving a new cluster profile revision,
not an environment variable.

A project with `clustering.automatic=false` is skipped by the refresh and by ingest-time
placement (read at each tick). Explicit clustering (`POST .../clusters/runs`, an
auto-label job) always runs. Neither calls the VLM unless a job asks for it.

## (c) VLM-assisted labeling of a large batch

Many unlabeled items, a VLM proposing classes under a budget. The VLM only looks at items
that have a `pe_embedding`; embed first if the policy was `lazy`.

**1. Provide a VLM.** Run one in the stack or register one elsewhere
([VLM selection](./vlm-selection.mdx#register-an-endpoint)):

```bash
./setup-openprocessor.sh --tiers core,curation,vlm        # installed directory
docker compose -p <project> --profile vlm up -d vlm       # compose
./openprocessor vlm list                                  # catalog
./openprocessor vlm use qwen3-vl-4b && ./openprocessor vlm probe
```

`vlm use` needs `OP_LOCAL_VLM_ENDPOINT`, which the installer sets with the `vlm` tier
([details](./vlm-selection.mdx#cli)).

**2. Activate it for the project:**

```bash
curl -s -X POST $API/curation/projects/cars/vlm/endpoints/env/activate \
  -H 'content-type: application/json' \
  -d '{"revision": null, "acknowledge_external": false, "force": false, "expected_active": null}'
```

Use `.../vlm/endpoints/host-vlm/activate` for a registered endpoint named `host-vlm`.

**3. Set scope and budget before anything runs.** The default scope `all` labels every
eligible crop. `representatives` labels the `per_cluster` crops nearest each cluster
centre plus every unassigned crop:

```bash
curl -s -X PUT $API/curation/projects/cars/vlm/policy \
  -H 'content-type: application/json' \
  -d '{"expected_revision": 0, "scope": "representatives", "per_cluster": 5,
       "max_crops_per_day": 2000}'
```

The continuous worker re-reads the policy about every 30 seconds.

**4. Run it.** Continuously, `curation-vlm-worker` labels embedded, unvalidated items
inside the policy. Or queue one job (a background job; poll `auto_label/status`):

```bash
curl -s -X POST "$API/curation/projects/cars/pipeline/auto_label/start?run_vlm=true&embed_missing=true"
curl -s "$API/curation/projects/cars/pipeline/auto_label/status"
```

A project with no VLM answers `409 vlm_not_configured` unless the request names an
endpoint with `vlm=<name>`. VLM labels stay unvalidated suggestions
(`class_source: "vlm"`) until a person validates them.

`vlm_attributes=true` also collects the pack's item attributes in the same call (needs
`run_vlm=true`, else `422 invalid_request`; a pack with no item attributes gives `422
pack_declares_no_attributes`).

A VLM run that labeled nothing fails with the counts (`failed` requests, `unreadable`
crops), for example when the endpoint is unreachable or the worker lacks the source mount.

## Recipe: cluster, name by hand, then run the VLM for one thing

Ingest, detect cars and people, cluster, name clusters yourself (say `spoiler`, a class
the detector lacks), and call the VLM only for the part you choose. `API` below is
`http://localhost:4603/curation/projects/cars`.

**1. Keep only cars and people** (this stores two of the 80 classes):

```bash
curl -s -X PUT $API/ingest/policy -H 'content-type: application/json' \
  -d '{"expected_revision":0,"detect":{"classes":["car","person"]},"embedding":{"mode":"all"}}'
```

**2. Ingest** (upload shown; a server folder: [Ingest sources](./ingest-sources.mdx)):

```bash
curl -s -X POST $API/ingest/upload -F images=@a.jpg -F images=@b.jpg
```

**3. Cluster with no VLM stage** (`run_vlm` defaults to false):

```bash
curl -s -X POST "$API/pipeline/auto_label/start?train_clusters=true&run_vlm=false"
curl -s $API/pipeline/auto_label/status
curl -s "$API/clusters?limit=20"
```

If clusters are too coarse, save a finer cluster profile, run `POST $API/clusters/runs`
(`{"target":"item"}`) and activate the new partition.

**4. Name a cluster by hand.** Create the class, list a cluster's crops, label them:

```bash
curl -s -X POST $API/classes -H 'content-type: application/json' \
  -d '{"name":"spoiler","group":"car_part"}'
curl -s "$API/crops?cluster_uid=<cluster uid>&limit=200"
curl -s -X PUT $API/crops/batch_label -H 'content-type: application/json' \
  -d '{"crop_ids":["050ad3a2...","05ad8ec2..."],"class_id":0,"label_source":"human"}'
```

These are now human-validated; no automated writer, the VLM included, overwrites them. In
Cropwright open the cluster and use **Label all matching…**.

**5. Run the VLM for one thing.** An assist run plans first (`dry_run` is the default).
A project without a VLM is refused with `409 vlm_not_configured`; name an endpoint for this
run and the project setting stays `off`:

```bash
curl -s -X POST "$API/assist/runs" -H 'content-type: application/json' \
  -d '{"target":{"kind":"cluster","cluster_id":10000},"actions":["classify"],"vlm":"env","dry_run":false}'
curl -s "$API/assist/runs/RUN_ID"
```

Human-validated members are sent for a suggestion but their class is never written
(`locked_suggest_only` in the result). Other scopes, all taking `vlm=<name>`:

| Scope | Request |
|---|---|
| A cluster or a sample of it | `POST $API/assist/runs`, `target` `{"kind":"cluster","cluster_uid":"..."}`, `sample` `{"mode":"representative"}` |
| Chosen crops | `POST $API/assist/runs`, `target` `{"kind":"crops","crop_ids":[...]}` |
| A class, confidence or size band | `POST $API/pipeline/auto_label/start?run_vlm=true&vlm=env&class_id=3&conf_max=0.5` (same filters as the crop list) |
| A budget | add `max_vlm_crops=200` to `auto_label/start` |
| Representatives only | `vlm_scope=representatives`, or the project [VLM policy](./vlm-selection.mdx#scope-and-budget) |

A cluster run returns a proposal (the agreed class, vote distribution, proposed new-class
slugs, attribute summary). Apply it only on purpose:

```bash
curl -s -X POST "$API/assist/runs/RUN_ID/apply" -H 'content-type: application/json' \
  -d '{"class_name":"spoiler","dry_run":true}'
```

`dry_run` counts what would be labelled and what is locked; send `"dry_run": false` to
label as a human would. After a new partition is activated, `scope_now.changed` is true and
apply refuses with `scope_changed` until you run again (or pass `allow_changed_scope`).
More: [Selective VLM and segmenter assist](./selective-assist.mdx) (the **Assist…** button
on a cluster page).

**Parts the detector lacks (a wheel, a spoiler).** Use a region profile so the segmenter
proposes the part inside each car with the VLM verifying
([wheels on cars](./wheel-example.mdx), [Region profiles](./region-profiles.mdx)), or label
against an open-vocabulary prompt set ([Open vocabulary](./open-vocabulary.mdx)). Both
call the VLM, so activate one first.

## (d) Iterative cluster-sampled auto-labeling

The loop samples crops from each cluster, labels them with the VLM, propagates the label
when the answers agree, and splits the cluster otherwise. It runs in
`curation-assist-loop-worker` under a required crop budget and can be rolled back. See
[Auto-label loop](./auto-label-loop.mdx).

## Troubleshooting

- **A worker is up but nothing happens:** [Health and stall reasons](../operations/health-and-stalls.mdx), [Workers and heartbeats](../operations/workers.mdx).
- **`409 vlm_not_configured`:** the project's VLM is off or no endpoint exists; activate one.
- **The VLM worker labels nothing:** items have no `pe_embedding` (policy `lazy`), the VLM policy scope excludes them, or the daily budget is used.
- **Clusters stopped refreshing:** check `clustering.automatic`, that a `cluster-worker` is up, and the profile's `refresh` rule.
