# Cluster list, sort and filters

`GET /curation/projects/{project}/clusters` serves the cluster cards the Cropwright cluster
page renders. The server computes the numbers, applies the filters, orders the cards and
raises the quality flags; the client only shows what it is served. Frozen test-holdout and
excluded items are never counted. Examples assume `API=http://localhost:4603` and project
`cars`.

## Sort

`sort` takes an id from the response's `sort_options` (default `size_desc`). A card without
the sorted value goes last; ties break on the cluster id.

| `sort` | Orders by |
|---|---|
| `needs_review_desc` | Members in the review queue, most first |
| `size_desc`, `size_asc` | Member count |
| `label_agreement_asc` | Least label agreement first |
| `detector_conf_asc` | Mean detector confidence, lowest first |
| `unvalidated_desc` | Members without a human-validated class, most first |
| `updated_desc` | Most recently updated |
| `dominant_class` | Dominant class name, alphabetical |

## Filters

Query parameters, combined with AND.

| Parameter | Effect |
|---|---|
| `dominant_class` (repeatable) | Cards whose dominant class name matches |
| `detector_class` (repeatable) | Cards whose detector top class matches |
| `min_size`, `max_size` | Member count range |
| `validation_state` | `none`, `partial` or `complete` |
| `flag` (repeatable) | Cards carrying any of these flags |
| `needs_review` | `true`: cards with members in the review queue; `false`: those without |
| `cluster_uid` | Exactly one card |
| `max_clusters` | Buckets the aggregation returns (default 1000, up to 10000) |

The shared item filter (`class_source`, `min_blur_ratio`, `class_name`, `conf_min`, ...)
narrows the members every card counts. `detector_class` keeps cards by their top class;
`detector_class_name` (an item filter) narrows the members inside the cards.

`offset` and `limit` page the representative crops only: every card up to `max_clusters` is
returned, and cards outside the window have an empty `representatives` list. `truncated: true`
means the aggregation hit `max_clusters`.

```bash
curl -s "$API/curation/projects/cars/clusters?sort=label_agreement_asc&flag=label_disagreement&min_size=20&limit=24"
```

## Card fields

Besides size, dominant class and representatives, a card has `display_name` and
`display_name_kind` (`class`, `detector` or `none`: the dominant class, else the detector's most
common class, the same rule an item follows), `near_dup_group_count` (how many
near-duplicate groups the members belong to), `label_agreement` (share of the
labelled members naming the top class), `detector_top_class`, `detector_top_share`,
`detector_conf_mean`, `validation_state`, `review_counts` per review tab,
`needs_review_count` and `flags`. The response also carries `sort`, `sort_options`,
`flag_vocabulary` and `truncated`.

## Quality flags

Decided by the server (`src/domain/cluster_flags.py`); `flag_vocabulary` gives each id, label
and description.

| Flag | Raised when |
|---|---|
| `mixed_detector_classes` | The detector's top class covers under 80 percent of the members that have one, in a cluster of at least 10 |
| `label_disagreement` | The top class covers under 90 percent of the labelled members, with at least 5 labelled |
| `needs_review` | At least one member is in the unified review queue |
| `unvalidated` | No member has a human-validated class |

`label_disagreement` and `mixed_detector_classes` mean a person should look before trusting a
bulk label; `unvalidated` plus `needs_review` is the natural work queue. A flag is a prompt to
look, not a verdict.

## Facets for one cluster

`GET /curation/projects/{project}/clusters/{cluster_uid}/facets` counts one cluster's members
by detector class (top 20), class source, validation state, review tab and detector
confidence (ten bins of 0.1, each with the `min` and `max` to send; the last has
`max: null`), plus the count with no detector confidence. Each count equals the `total` of the
matching filtered `GET .../crops` call (`detector_class_name`, `label_validated`, `review_tab`,
`detector_conf_min`, `detector_conf_max`, the last exclusive). An unknown or empty cluster
answers zeros. `GET .../crops` also sorts by `detector_confidence`.

## In Cropwright

The cluster page sends `sort` and the filters and shows the served order and flag labels.
Facet chips apply the matching crops filter. The choice is kept in the page URL (and session
storage when the URL has none); "Clear filters" resets it. User guide:
[Clusters](../cropwright/user-guide/workspace.md).
