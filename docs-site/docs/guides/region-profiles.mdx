# Region profiles

A region profile defines what counts as a region of interest inside an item: which detector
and segmenter find candidates, how many boxes an item may carry, which items get the region
stage, and whether text is read. A wheel on a car, a plate on a vehicle, a defect on a part:
each is one profile. It is data, editable per project, versioned and revertible.

Examples assume `API=http://localhost:4603` and project `cars`.

## Concepts

- **Item and region.** An item is a crop from the primary detector; the region stage looks
  for sub-regions inside it. With no active profile, region detection is off.
- **Legs.** A detector leg (Triton model `detector_model`) and a segmenter leg (text prompt
  `segmenter_text_prompt`). At least one is required; if the segmenter is the only leg, the
  prompt is mandatory.
- **Scope and count.** `parent_classes` lists item class names that get the region stage
  (empty = every item). `max_regions_per_item` (1 to 64, default 1) is the most boxes kept
  per item; see [Multi-box regions](./multi-box-regions.mdx).
- **Text.** `text_reader` is `none`, `vlm`, `ocr`, `vlm_then_ocr` (OCR when the VLM read
  nothing) or `both` (store both, flag a disagreement). The `text_*` fields tune
  normalization and validity.
- **Display.** `display_name` / `display_name_singular` are the frontend labels;
  `region_class_name` is the registry class the detections are treated as.
- **Sources and revisions.** As for prompt packs: `builtin`, `file` (`OP_REGION_PROFILE_PATH`),
  `template` (`examples/region_profiles/`), `stored`. Only stored profiles are editable; each
  save is a numbered revision.
- **Activation.** One profile is active per project, or none. Activation passes a gate that
  pairs it with the active prompt pack and VLM, and never rewrites existing items; the
  impact route counts what is stale and suggests a reprocess.

## Routes

Under `/curation/projects/{project}/region_profiles`:

| Call | Purpose |
|---|---|
| `GET` (`include_templates=true`), `POST` | List / create a stored profile |
| `GET /schema` | Fields with ranges and choice sources |
| `POST /validate`, `POST /validate_segmenter_prompt` | Validate a draft or one prompt; never writes |
| `POST /test` | Dry run on a crop ([Test on a crop](./test-on-crop.mdx)) |
| `GET /active`, `GET /active/impact` | Active profile and what workers applied / what activation means for existing items |
| `POST /active/rollback`, `POST /deactivate` | Re-activate the previous / switch region detection off |
| `GET`, `PUT`, `DELETE /{name}` | One profile / new revision / delete |
| `POST /{name}/activate`, `POST /{name}/clone` | Activate / copy |
| `GET /{name}/revisions[/{revision}]` | History |

```bash
curl -s "$API/curation/projects/cars/region_profiles?include_templates=true"
curl -s "$API/curation/projects/cars/region_profiles/vehicle_wheel"
```

The list has `profiles` (`name`, `detector_model`, `segmenter_text_prompt`, `parent_classes`,
`max_regions_per_item`, `text_reader`, `reads_text`, `region_class_name`, `read_only`,
`revision`, `active`), `templates`, `active` and `config_revision`. A document adds `body`,
`description`, `etag`, `cloned_from` and `effective` (which legs run, whether text is read,
whether the OCR text-hint re-pass is active).

## Profile fields

The schema route returns every field with ranges; defaults not shown are in
`src/config/detection_profile.py`.

| Group | Fields |
|---|---|
| Identity and scope | `display_name`, `display_name_singular`, `region_class_name`, `parent_classes` |
| Detector leg | `detector_model` (empty = none), `detector_version`, `input_size` (640, multiple of 32), `confidence_floor` (0.4), `batch_limit` (16), `letterbox_fill` |
| Segmenter leg | `segmenter_name` (`sam3`), `segmenter_version`, `segmenter_text_prompt` (empty = off) |
| Segmenter gating | `gate_hit_rate` (false), `gate_hit_window` (20), `gate_hit_miss_threshold` (15), `gate_hit_sample_floor` (0.1): skip the segmenter for an item class that keeps missing, still sampling it; skipped items are stamped `region_gate_skip` (reprocess filter `region_gate_skipped`); never for a class a human owns |
| Selection | `max_regions_per_item` (1), `region_nms_iou` (0.5), `auto_confirm_aspect`, `auto_confirm_area_frac` |
| Text reading | `text_reader` (`vlm_then_ocr`), `text_pattern`, `text_format`, `text_charset`, `text_uppercase`, `text_join`, `text_len_min`, `text_len_max`, `text_stopwords`, `text_min_confidence`, `text_placeholders`, `text_reject_sequences`, `text_crop_margin`, `text_crop_min_height`, `text_min_height_ratio`, `text_border_margin` |
| OCR | `ocr_pipeline_model`, `ocr_rec_model`, `ocr_rec_version`, and the text hint: `text_hint_enabled` (true), `text_hint_aspect_min/max`, `text_hint_len_min/max`, `text_hint_rec_floor`, `text_hint_require_letters_and_digits` |
| Other | `human_detector_name`, `human_detector_version`, `secondary_shape_groups`, `assigns_class`, `labels_path` |

The segmenter prompt is one line of plain text, at most 200 characters and 8 comma-separated
phrases.

## Validate

```bash
curl -s -X POST "$API/curation/projects/cars/region_profiles/validate?for_activation=true" \
  -H 'Content-Type: application/json' \
  -d '{"name": "vehicle_wheel_v2",
       "body": {"segmenter_text_prompt": "wheel", "parent_classes": ["car"],
                "max_regions_per_item": 4, "text_reader": "none", "text_hint_enabled": false,
                "ocr_pipeline_model": "", "region_class_name": "wheel",
                "display_name": "Wheels", "display_name_singular": "Wheel"}}'
curl -s -X POST "$API/curation/projects/cars/region_profiles/validate_segmenter_prompt" \
  -H 'Content-Type: application/json' -d '{"text_prompt": "wheel", "sole_leg": true}'
```

The body may be partial; missing fields take defaults. With `for_activation=true`,
unreachable or not-ready dependencies are errors instead of warnings. The response is
`{ok, errors, warnings, force_allowed}`.

| Code | Severity | Meaning |
|---|---|---|
| `profile_name_invalid`, `profile_name_reserved`, `name_conflict` | error | Name must match `^[a-z0-9][a-z0-9_.-]{1,63}$`; `off`, `none`, `default` reserved |
| `profile_field_unknown`, `profile_field_type`, `profile_field_range` | error | Unknown field, wrong type, out of range |
| `region_class_name_invalid`, `text_reader_invalid`, `text_regex_invalid` | error | Bad class name, reader mode or regex |
| `no_candidate_source` | error | Neither a detector model nor a segmenter prompt |
| `segmenter_prompt_empty` | error if sole leg, else warning | Empty prompt |
| `segmenter_prompt_too_long`, `..._too_many_phrases`, `..._multiline` | error | Over the prompt limits |
| `detector_model_not_found` | error | Model not in the Triton repository |
| `detector_model_not_ready` | warning, error for activation; bypassable | Model not READY |
| `detector_model_unusable` | warning on save, error for activation | The model has no `output0` tensor (for example a YOLO end-to-end model), so every item would end `no_region_box` |
| `detector_model_not_shared`, `detector_model_other_project`, `detector_model_classes_unmapped` | error, warning | Model belongs to another project and is not shared / is shared / has classes with no name match here |
| `triton_unreachable`, `segmenter_unreachable`, `ocr_model_not_ready` | warning, error for activation; bypassable | Dependency down |
| `segmenter_not_configured` | warning | `OP_SEGMENTER_URL` is not set |
| `ocr_model_not_found` | error | OCR model not in Triton |
| `vlm_not_configured` | warning | A text mode needs a VLM and none is configured; it falls back to OCR |
| `text_fields_ignored`, `text_hint_inactive_no_ocr`, `display_name_missing`, `parent_class_unknown` | warning | Ignored text fields; hint without OCR; UI will say "Regions"; class not in the registry |
| `pack_multi_region_keys_missing` | error on activation | The active pack lacks the per-box reply keys |

## Create, edit, clone

```bash
curl -s -X POST "$API/curation/projects/cars/region_profiles/vehicle_wheel/clone" \
  -H 'Content-Type: application/json' \
  -d '{"new_name": "cars_wheels", "description": "Wheels on car crops"}'
curl -s -X PUT "$API/curation/projects/cars/region_profiles/cars_wheels" \
  -H 'Content-Type: application/json' \
  -d '{"expected_revision": 1, "description": "allow 6 wheels", "body": { ...fields... }}'
```

`POST .../region_profiles` creates from scratch (`name`, `description`, `body`). Clone takes
optional `revision` and `from_project`. Create and save refuse validation errors with 422;
warnings do not block.

## Activate, impact, roll back, deactivate

```bash
curl -s -X POST "$API/curation/projects/cars/region_profiles/cars_wheels/activate" \
  -H 'Content-Type: application/json' \
  -d '{"revision": null, "force": false, "expected_active": null}'
curl -s "$API/curation/projects/cars/region_profiles/active/impact"
curl -s -X POST "$API/curation/projects/cars/region_profiles/active/rollback" \
  -H 'Content-Type: application/json' -d '{"expected_active": null}'
curl -s -X POST "$API/curation/projects/cars/region_profiles/deactivate" \
  -H 'Content-Type: application/json' -d '{"expected_active": null}'
```

`force` bypasses only the bypassable codes above (a dependency down or not ready), never a
structural error. The activate response has `active`, `previous`, `applied`, `impact` and
`validation`. Workers switch at a quiet point.

| `impact` field | Meaning |
|---|---|
| `items_total` | Items in the project |
| `by_profile` | Item counts per profile name and revision that produced their regions |
| `validated_items`, `unseeded_items` | Human-validated regions; no profile stamp |
| `pending_items`, `pending_not_matching` | Waiting for detection; outside the new scope |
| `stale_items` | Machine-written items the active revision did not produce |
| `suggested_reprocess` | A dry-run reprocess request selecting the stale items, or null |

To apply a new profile to old items, post `suggested_reprocess` to the reprocess route
([Reprocess](./reprocess.mdx)). Delete (`DELETE .../{name}?expected_revision=2`) answers 204
and is refused while the profile is active.

## Errors

| Status | `error` | When |
|---|---|---|
| 404 | `not_found`, `unknown_revision` | Unknown or not-stored profile; no such revision |
| 403 | `read_only` | Save or delete of a built-in, file or template profile |
| 409 | `name_conflict`, `revision_conflict` | Name used; stale `expected_revision` |
| 409 | `in_use` | Delete of the active profile |
| 409 | `active_conflict` | Another writer changed the activation (`current` returned) |
| 409 | `no_previous`, `previous_deleted` | Nothing to roll back to |
| 422 | `validation_failed` | Validation errors (`report` lists them) |

An assist run with the `segment` action (`POST .../assist/runs`) re-runs the segmenter on
chosen items and waits in `waiting_region` while the region worker handles them. It answers
`409 region_profile_required` with no active profile, `no_segmenter_leg` when the profile has
no `segmenter_text_prompt`, `region_stage_paused` while the stage is paused, and
`verify_endpoint_mismatch` when `segment.verify` is `vlm` but the run names another endpoint
than the project's.
