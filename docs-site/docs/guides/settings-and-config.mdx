# Settings and configuration

Domain behavior is data, not code. A project keeps its configuration in the config store and
the API reads and writes it. This page covers the project settings document, the vocabulary
route that lists every model choice, and cloning settings between projects. Examples assume
`API=http://localhost:4603` and project `cars`.

## Concepts

- **Config store.** Per-project versioned documents: prompt packs, region profiles, ingest
  profiles, the keymap and one activation document per axis. Every save is a new revision;
  activating points the project at one revision. See [Prompt packs](./prompt-packs.mdx),
  [Region profiles](./region-profiles.mdx), [Keymaps](./keymaps.mdx).
- **Activation axes.** `prompt_pack`, `detection_profile` and `vlm` (the VLM names an endpoint
  from the global registry, [VLM selection](./vlm-selection.mdx)). A new activation is checked
  as a set: pack, profile and VLM must agree.
- **Settings document.** One per project, holding default strategy ids for UI-facing axes. Not
  for secrets or deployment values.
- **Deployment configuration.** Values in `.env` (ingest detectors, segmenter service); they
  change only with a restart.

## Read and write settings

```bash
curl -s "$API/curation/projects/cars/settings"
```

```json
{"defaults": {"prompt_pack": "vehicle_wheel", "detection_profile": "vehicle_wheel", "vlm": "env"},
 "updated_at": null, "updated_by": null}
```

`defaults` maps axis id to strategy id (empty when no document exists).
`prompt_pack`, `detection_profile` and `vlm` are read from the activations, not from the
document. `updated_by` is always null (no user accounts).

Update with a partial body; only present axes change, and `null` clears one:

```bash
curl -s -X PUT "$API/curation/projects/cars/settings" -H 'Content-Type: application/json' \
  -d '{"defaults": {"sort": "uncertainty", "detection_profile": "vehicle_wheel"}}'
```

Settable axes: `cluster`, `sort`, `prompt_pack`, `detection_profile`, `vlm`. A `cluster` or
`sort` id must be listed by `GET .../methods`, and a sort by a field no item has is refused.
A `prompt_pack` or `detection_profile` id must exist (`detection_profile` also accepts
`off`). A body changing several config-store axes is checked as one set and applied only if
every part passes.

| Status | `error` | When |
|---|---|---|
| 422 | (plain message) | Unsettable axis, id not advertised, or a sort field with no coverage |
| 422 | `unknown_vlm`, `unknown_pack`, `unknown_profile` | Unknown endpoint, pack or profile (`valid_ids` returned for the last two) |
| 422 | `validation_failed` | The activation gate refused the combination (`report` lists the issues) |
| 409 | `active_conflict`, `project_archived` | Another writer changed the activation; project archived |

## Vocabulary

One call returns every choice a configuration form needs:

```bash
curl -s "$API/curation/projects/cars/config/vocabulary"
curl -s "$API/curation/projects/cars/config/vocabulary?include_other_projects=true"
```

| Field | Content |
|---|---|
| `detectors` | Triton and promoted detector models, with `ready` and `source` |
| `segmenters` | Segmenter services with `endpoint`, `status`, `masks`, default score |
| `vlm` | `active` endpoint and every registered endpoint with locality and status |
| `ocr` | OCR detection, recognition and pipeline models |
| `text_reader_modes` | Valid modes, and whether each needs OCR or a VLM |
| `prompt_pack_calls` | The VLM call ids a pack must cover |
| `registry_classes` | Active (not deprecated) classes |
| `model_choices` | The table below |

`include_other_projects=true` adds detector models other projects share.

Each `model_choices` row has `role`, `scope`, `current`, `settable`, `settable_via` and, when
not settable, `reason`:

| Role | Scope | Settable | How |
|---|---|---|---|
| `detect_model` | per request | yes | `model_name` query parameter on the detect routes |
| `item_detector` | deployment | no | `OP_INGEST_PRIMARY_DETECTOR_MODEL` (restart); a project's active [ingest profile](./ingest-profiles.mdx) overrides it for that project |
| `secondary_classifier` | deployment | no | `OP_INGEST_SECONDARY_DETECTOR_MODEL` (restart) |
| `region_detector` | region profile | yes | `detector_model` in the profile |
| `region_segmenter` | deployment | no | `OP_SEGMENTER_URL` or `OP_SEGMENTER_URLS`; the prompt is per profile |
| `region_ocr` | region profile | yes | OCR model fields in the profile |
| `vlm` | config store | yes | Activate an endpoint, or pass `vlm` per run |
| `local_vlm_model` | deployment | only with an in-compose VLM | Select a catalog entry, then run the host command |
| `item_embedding`, `search_embedding` | deployment | no | Changing them changes vector size and needs a re-index (future work) |
| `face_models` | deployment | no | Fixed pipeline |
| `training_size` | per run | yes | `model_size` when starting a training run |

## Clone settings between projects

Copy configuration into an existing `active` project; a clone is a starting point, never a merge:

```bash
curl -s -X POST "$API/curation/projects/cars/clone_settings" -H 'Content-Type: application/json' \
  -d '{"from": "default", "axes": ["classes", "prompt_packs", "keymap"], "expected_revision": 2}'
```

`axes` (optional; omitted or empty = all): `settings_defaults`, `classes`, `activations`,
`keymap`, `prompt_packs`, `vlm_activation`. The response is the project lifecycle envelope.
If a copied keymap action collides with a class hotkey in the target, the whole keymap is
skipped and each collision is listed in `keymap_clone_conflicts` (`action_id`, `combo`,
`class_id`, `class_name`); nothing is unbound silently. The same options exist at create time
as `clone_settings_from` / `clone_axes` ([Projects](./projects.mdx)).

| Status | `error` | When |
|---|---|---|
| 404 | `project_not_found` | Target or source unknown |
| 409 | `clone_source_not_ready` | Source is not `active` or `archived` |
| 409 | `target_not_empty` | `classes`: target has items. `prompt_packs`: target has stored packs. `activations`: target has an active pack or profile, or a stored one with the same name |
| 409 | `revision_conflict` | Stale `expected_revision` |
| 422 | `combine_invalid` | Unknown axis, or source equals target |
| 422 | `validation_failed` | A copied activation fails its gate in the target |

Where per-project data lives is set by `OP_PROJECTS_DATA_ROOT`, `OP_PROJECT_INDEX_PREFIX` and
`OP_STATE_DIR`; VLM policy by `OP_VLM_EXTERNAL_POLICY`, `OP_VLM_SECRETS_DIR` and
`OP_LOCAL_VLM_ENDPOINT`. See [Basic configuration](../configuration/basic.mdx) and
[Advanced configuration](../configuration/advanced.mdx).
