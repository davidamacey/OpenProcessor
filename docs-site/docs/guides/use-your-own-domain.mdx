# Use your own domain

The pipeline is not tied to one image domain. You configure a new domain with classes, a
region profile, a prompt pack and a VLM endpoint instead of changing code. The
[wheel example](./wheel-example.mdx) is this path with real files; the snippets below use it.

`API=http://localhost:4603/curation/projects/<project>` is assumed, with the project from
step 1.

## Before you start

- **An item detector** in Triton that proposes your objects. A stock 80-class COCO YOLO works
  to start and keeps its full vocabulary (do not set a class-id filter). Activate an
  [ingest profile](./ingest-profiles.mdx) for the project, or set
  `OP_INGEST_PRIMARY_DETECTOR_MODEL`. See [Model export](../getting-started/model-export.mdx).
- **The PE image encoder** (`make export-pe`). Without it ingest writes no embeddings, and
  search, near-duplicates and clustering have nothing to work on.
- Optional: the segmenter service (`OP_SEGMENTER_URL`) for a region stage; a VLM for
  verification and labeling.

## 1. Create a project

```bash
curl -s -X POST http://localhost:4603/curation/projects \
  -H 'Content-Type: application/json' \
  -d '{"slug": "wheels", "display_name": "Wheels"}'
API=http://localhost:4603/curation/projects/wheels
```

`clone_settings_from` (and `clone_axes`) starts from another project's settings. See
[Projects](./projects.mdx).

## 2. Define classes

Classes are identified by name (`^[a-z0-9_]+$`; a duplicate is 409).

```bash
for name in car wheel; do
  curl -s -X POST "$API/classes" -H 'Content-Type: application/json' \
    -d "{\"name\": \"$name\", \"group\": \"vehicle\"}"
done
curl -s "$API/classes"
```

Each entry reports `class_id`, `kind` (`item` or `region`), `sample_count`,
`validated_count`, `trainable`; `hotkey_letter` sets a review key ([Keymaps](./keymaps.mdx)).
`POST .../classes/seed_from_detector` seeds the registry from the detector's label space
(dry run by default, by name, idempotent). A class is its name everywhere: import, combine,
export, train and promote never carry a raw class index across a boundary.

## 3. Write a region profile (optional)

Skip if items are the whole object. Start from `examples/region_profiles/vehicle_wheel.json`:

| Field | Wheel example | Meaning |
|---|---|---|
| `parent_classes` | `["car"]` | The region stage runs only on these item classes |
| `segmenter_text_prompt` | `wheel` | What the segmenter looks for |
| `detector_model` | empty | No detector leg until you train and promote one |
| `max_regions_per_item` | 4 | Box cap per item |
| `text_reader` | `none` | A text-free region |
| `region_class_name` | `wheel` | The class name used on export |

```bash
BODY=$(jq '{name: "wheel_example", body: del(._comment, .name)}' \
  examples/region_profiles/vehicle_wheel.json)
curl -s -X POST "$API/region_profiles/validate" -H 'Content-Type: application/json' -d "$BODY"
curl -s -X POST "$API/region_profiles" -H 'Content-Type: application/json' -d "$BODY"
curl -s -X POST "$API/region_profiles/wheel_example/activate" \
  -H 'Content-Type: application/json' -d '{"expected_active": null}'
```

See [Region profiles](./region-profiles.mdx) and [Multi-box regions](./multi-box-regions.mdx).

## 4. Write a prompt pack

Start from `examples/prompt_packs/vehicle_wheel.json` (or `general_objects.json`, with three
plain item attributes) or a built-in pack. `GET .../prompt_packs/schema` lists the reply keys
to keep.

```bash
BODY=$(jq '{name: "wheel_example", body: del(._comment, .name)}' \
  examples/prompt_packs/vehicle_wheel.json)
curl -s -X POST "$API/prompt_packs" -H 'Content-Type: application/json' -d "$BODY"
curl -s -X POST "$API/prompt_packs/wheel_example/activate" \
  -H 'Content-Type: application/json' -d '{"expected_active": null}'
```

Try the pack on stored crops first, writing nothing: [Prompt packs](./prompt-packs.mdx),
[Test on a crop](./test-on-crop.mdx).

## 5. Choose a VLM endpoint

Register, probe and activate one. A new project calls no VLM until it activates one, and the
region worker leaves the segmenter's boxes unverified.

```bash
curl -s -X POST http://localhost:4603/curation/vlm/endpoints -H 'Content-Type: application/json' \
  -d '{"name": "host-vlm", "body": {"base_url": "http://host.docker.internal:8012/v1", "model": "my-vision-model"}}'
curl -s -X POST http://localhost:4603/curation/vlm/endpoints/host-vlm/probe
curl -s -X POST "$API/vlm/endpoints/host-vlm/activate" -H 'Content-Type: application/json' -d '{}'
```

The built-in `env` endpoint (`OP_VLM_URL`, `OP_VLM_MODEL`) is activated the same way. See
[VLM selection](./vlm-selection.mdx).

## 6. Ingest or import

Both the API and the detection worker mount `OP_SOURCE_ROOT_HOST` at `/data/source`.

```bash
curl -s -X POST "$API/ingest/batch" -H 'Content-Type: application/json' \
  -d '{"items": [{"path": "/data/source/my_images/001.jpg", "source": "my_images"}]}'
curl -s "$API/ingest/region_drain"     # repeat until "drained" is true
```

`GET .../ingest/config` lists the accepted source roots. For a whole folder or manifest use
`scripts/curation/bulk_ingest.py` ([Ingest a large folder](./ingest-large-folder.mdx)). An
already-labeled dataset is imported instead ([Dataset import](./dataset-import.mdx)); to merge
projects see [Combine projects](./combine-projects.mdx). After changing a profile or pack,
apply it to existing items with [Reprocess](./reprocess.mdx).

## 7. Review

Use Cropwright or the routes:

```bash
curl -s "$API/review/tabs"                 # every tab with its filters
curl -s "$API/review/<tab>?page_size=50"
curl -s -X PUT "$API/crops/CROP_ID/label" -H 'Content-Type: application/json' -d '{"class_id": 0}'
```

Confirm, move, add or reject boxes with the [multi-box routes](./multi-box-regions.mdx),
cluster items to label many at once and mark false positives. Every human edit is locked:
automated stages never overwrite it.

## 8. Export and train

Freeze a test holdout first, so models are scored on items they never train on:

```bash
curl -s -X POST "$API/test_holdout/freeze" -H 'Content-Type: application/json' -d '{"percent": 10}'
curl -s -X POST "$API/export/yolo" -H 'Content-Type: application/json' -d '{}'
# or one class; for a region class positives are accepted boxes cropped to the parent:
curl -s -X POST "$API/export/single_class" -H 'Content-Type: application/json' \
  -d '{"profile_name": "wheels", "box_source": "region", "region_class_name": "wheel",
       "image_mode": "item_crop", "class_ids": []}'
```

Train with the trainer service (`docker compose --profile training up -d curation-trainer`):

```bash
curl -s -X POST "$API/train/preflight" -H 'Content-Type: application/json' -d '{}'
curl -s -X POST "$API/train/start" -H 'Content-Type: application/json' -d '{
  "model_family": "yolo26", "model_size": "s", "profile": "small",
  "hyperparameters": {"epochs": 70, "imgsz": 640, "batch": 16}}'
curl -s "$API/train/runs"
```

`start` returns 201 with `job_id` and the preflight report; a blocking preflight check is
422 unless `force=true`. Copy profile defaults from `GET .../train/profiles` into
`hyperparameters`. When the run finishes, promote it to Triton:

```bash
curl -s --max-time 300 -X POST "$API/train/promote/JOB_ID?wait=true" \
  -H 'Content-Type: application/json' -d '{"triton_name": "wheel_detector", "force": false}'
```

Promote is gated on the run's metrics (`force` in the body or `?force=true` bypasses). A
subset or single-class run needs its class remap, and promote refuses rather than serve the
full registry as the trained subset. After promoting a region detector, set `detector_model`
in the region profile to its Triton name, then reprocess. Compare detectors with the bake-off
routes under `.../bakeoff/`. See [Training and promote](../operations/training-and-promote.mdx)
and [Curation workflow](../operations/curation-workflow.mdx).
