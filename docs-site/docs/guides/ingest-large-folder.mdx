# Ingest a large folder

Take a photo share (NAS) to a finished bulk ingest: mount it, run a small trial, run
the whole folder, recover from a stop. For S3 or watched sources see
[Ingest from S3 and watched sources](./ingest-sources.mdx).

Checklist before you start:

- `./openprocessor health` is green.
- A detector is available: activate an [ingest profile](./ingest-profiles.mdx) or set
  `OP_INGEST_PRIMARY_DETECTOR_MODEL`. Otherwise ingest answers 503
  `No detector configured for ingest`.
- A fresh project exists and its [ingest policy](./ingest-policy.mdx) is set (a policy
  only affects future ingests).

Paths below use `/srv/nas/photos` on the host and `/data/source` inside the containers.
Ingest commands take the **container** path.

## 1. Mount the share and point the stack at it

Mount read-only on the Docker host. The container user (uid 1000) must be able to read
every directory.

```bash
sudo mount -t nfs -o ro nas.example.lan:/export/photos /srv/nas/photos
# SMB: sudo mount -t cifs -o ro,uid=1000,credentials=/root/.nas-credentials //nas.example.lan/photos /srv/nas/photos
```

Set the host path in `.env` and recreate the services (`restart` does not re-read `.env`):

```bash
OP_SOURCE_ROOT_HOST=/srv/nas/photos
./openprocessor start
```

Compose mounts it read-only at `/data/source` in `api`, `curation-detection-worker`,
`curation-auto-label-worker` and `curation-assist-loop-worker`. A worker without the
mount gives 404 thumbnails and a VLM stage that predicts 0 labels.

Check what the API sees. `source_roots` must list `/data/source`; the response also
gives the batch and concurrency limits:

```bash
curl -s http://localhost:4603/curation/projects/<slug>/ingest/bulk/config
```

### A second share

`OP_SOURCE_ROOT_HOST` is one root. Name more with `OP_SOURCE_PATH_ALIASES`
(`alias=path` pairs or JSON; no `/` in an alias; a malformed value is rejected) and
bind-mount them yourself in `docker-compose.local.yml` (git-ignored; `./openprocessor` and
`make` load it, `docker-compose.override.yml` is not read):

```bash
OP_SOURCE_PATH_ALIASES=archive=/data/archive
```

```yaml
services:
  api:
    volumes: ["/srv/nas/archive:/data/archive:ro"]
  curation-detection-worker:
    volumes: ["/srv/nas/archive:/data/archive:ro"]
  curation-auto-label-worker:
    volumes: ["/srv/nas/archive:/data/archive:ro"]
  curation-assist-loop-worker:
    volumes: ["/srv/nas/archive:/data/archive:ro"]
```

Then ingest `--folder /data/archive/2023`.

## 2. Create a project

```bash
curl -s -X POST http://localhost:4603/curation/projects \
  -H 'content-type: application/json' \
  -d '{"slug": "nas-photos", "display_name": "NAS photos"}'
```

Add `"clone_settings_from": "<other-slug>"` to copy settings. Slug rules are in
[Projects](./projects.mdx).

## 3. Preview, then a trial of 200 to 500 images

A preview walks the source read-only and ingests nothing. It returns file count, bytes,
extensions, image-size sample, skipped directories and symlinks, and an estimate of time
and index size. In Cropwright press **Preview** next to **Start bulk ingest**.

```bash
docker compose -p <project> exec api python scripts/curation/bulk_ingest.py \
  --project nas-photos --folder /data/source/2024-03-sat \
  --api-base http://localhost:8000/curation --preview
```

Route: `POST /curation/projects/{project}/ingest/bulk/preview` (one of `folder`,
`manifest`, `s3`, `source_id`). The walk stops at 200,000 files or 60 seconds and then
reports `partial: true` (figures are lower bounds). Estimates use measured figures from
`docs/PERFORMANCE.md` on one RTX A6000; treat them as an order of magnitude.

Then run a slice: a sub-folder, or a manifest (text file, one container path per line,
or JSON Lines with `path`). **The manifest itself must lie under a source root.**

```bash
docker compose -p <project> exec api python scripts/curation/bulk_ingest.py \
  --project nas-photos --manifest /data/source/trial.txt --source nas-trial
```

```text
completed              300/300 ingested 300 duplicate 0 failed 0 | 26.6 img/s eta --
  crops 1926, embedded 1926, not embedded 0 (0 encoder failures)
```

From the result take: the **speed** (images per second), the **items per image**
(crops / images, drives index size) and whether thumbnails load in Cropwright. Preview
a policy change on the stored data without writing:

```bash
curl -s -X POST http://localhost:4603/curation/projects/nas-photos/ingest/policy/preview \
  -H 'content-type: application/json' -d '{"embedding": {"mode": "lazy"}}'
```

Re-running the same images costs almost nothing: stored images are recognised by content
hash and reported as `duplicate`. If the policy was wrong, delete the project and start
over, since a policy change does not rewrite stored items.

## 4. Full run

```bash
docker compose -p <project> exec api python scripts/curation/bulk_ingest.py \
  --project nas-photos --folder /data/source
```

Inside `api` the default `--api-base` is `http://localhost:8000/curation`; on the host it
is `http://localhost:4603/curation`.

| Flag | Meaning |
|---|---|
| `--folder PATH` / `--manifest PATH` | The source (container path, under a source root). One of these, `--status` or `--cancel` is required. |
| `--preview` | Print the preview and exit. Also works with `--s3` and `--source-id`. |
| `--status RUN_ID` / `--cancel RUN_ID` | Show or stop a run. |
| `--project SLUG` | Default `$OP_CURATION_PROJECT`, else `default`. |
| `--api-base URL` | Curation API mount. |
| `--source TAG` | Provenance tag (default `bulk_ingest`). |
| `--extensions LIST` | Default `jpg,jpeg,png`. |
| `--batch-size N` / `--concurrency N` | Server default 16 each; maximum 64 and 32. |
| `--poll-interval S` / `--no-wait` | Progress interval (2 s); start and exit. |
| `--show-failures N` | Failed images printed at the end (20). |

Exit codes: `0` completed, `1` completed with failed images, `2` failed, `130` cancelled.

For a share the server cannot mount, `scripts/curation/ingest_upload.py --root DIR`
uploads the bytes from the client; they are copied into the project's upload root, so
plan disk for them.

**Cropwright:** Ingest page, **Bulk ingest (folder or manifest)**. Choose Folder or
Manifest, enter the container path, press **Start bulk ingest**. **Advanced** sets
extensions, batch size and concurrency. The run belongs to the server and keeps going
when you close the page.

More: [Ingest in Cropwright](../cropwright/user-guide/ingest.md).

## 5. Progress, cancel, resume, failures

A bulk run is a background job (`POST .../ingest/bulk` answers 202).

```bash
B=http://localhost:4603/curation/projects/nas-photos/ingest/bulk
curl -s $B                       # list runs
curl -s $B/<run_id>              # one run
curl -s -X POST $B/<run_id>/cancel
curl -s "$B/<run_id>/failures?offset=0&limit=100"
```

- **Progress:** `status`, `progress.discovered`, `progress.discovery_complete`, seconds
  per stage. A folder is scanned while it ingests, so `discovered` grows until
  `discovery_complete` is true.
- **Cancel:** stops after the batches in flight; stored images stay. In the script,
  Ctrl-C once cancels, twice detaches.
- **Resume:** start the **same source** again. An interrupted, failed, cancelled or
  `completed_with_errors` run continues (`resumed: true`); stored images are skipped. A
  cleanly completed source starts a new run.
- **One run at a time per project:** a second start gets 409 `bulk_ingest_busy`.
- **Automatic stop:** 5 batches in a row with every image failed ends the run as
  `failed` (detector or datastore down). Fix the cause and start again.
- **Skipped silently:** symbolic links, and directories that cannot be listed. If
  `discovered` is lower than the share, look there first.

## 6. Time and disk

`hours = images / (images_per_second x 3600)`; use the rate from your trial.
Measured on an RTX A6000 (`docs/PERFORMANCE.md`):

| What | Rate |
|---|---|
| Public COCO frames, one card | about 29 images/s |
| 12 to 24 MP photos, CPU decode | 27 images/s |
| The same, GPU decode | 35 images/s |
| 100,000 camera-original 20 MP JPEGs from a NAS, stopped and resumed once | 21 images/s |

**GPU decode.** `OP_INGEST_GPU_DECODE` (code default on; the installer writes `1` for the
`full` profile, `0` for `minimal` and `standard`) decodes JPEGs of at least
`OP_INGEST_GPU_MIN_MEGAPIXELS` (3.0) on the GPU. It needs about 8.5 GB more VRAM on the
Triton card; if the model cannot load, photos decode on the CPU. Non-baseline JPEGs fall
back to the CPU. Check with `./openprocessor gpu plan`; change in `.env` and recreate.

**Disk.** A folder ingest reads files in place and copies nothing; uploads are copied
into the project's upload root. Index cost per 1,000 images is roughly 22 MB (narrow
detector, every item embedded) to 80 MB (80-class vocabulary, every item embedded), an
upper bound for new projects (Lucene engine, about 4.5 KiB per item). Search keeps the
vector graph in RAM; see [Sizing and storage](../deployment/sizing-and-storage.mdx) and
[GPU sizing](../deployment/gpu-sizing.mdx). Check `df -h /var/lib/docker` before a long
run.

## Troubleshooting

| You see | Fix |
|---|---|
| 503 `No detector configured for ingest` | Activate an ingest profile or set `OP_INGEST_PRIMARY_DETECTOR_MODEL`. |
| 422 `bulk_ingest_invalid_source` | Path is not under a source root or does not exist. Use the container path; check `ingest/bulk/config`. |
| Thumbnails 404, VLM predicts 0 | A worker lacks the source or alias mount. |
| 409 `bulk_ingest_busy` | Another run is live; watch with `--status` or cancel it. |
| Script cannot connect | Pass `--api-base` (`localhost:8000` inside `api`, `4603` on the host). |
| Run `failed` right after start | Read `error` in `GET .../ingest/bulk/<run_id>`, fix, start the same source again. |
