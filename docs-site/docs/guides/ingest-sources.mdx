# Ingest from S3 and watched sources

Bring images in from an S3 bucket (AWS, MinIO or any S3-compatible store) and keep a
project current with a poll, a cron schedule or S3 event webhooks. A folder is a source
too; for a one-time import of a mounted folder see
[Ingest a large folder](./ingest-large-folder.mdx). Triggers apply to folder sources as well.

Before you start: the stack is healthy, a detector is configured, the project exists and
its [ingest policy](./ingest-policy.mdx) is set, and the `api` container can reach the
bucket.

## How it works

1. Something notices a new object: a scan (manual, poll or cron) or an S3 event. Each
   object becomes a row `(key, etag)` in the source's queue (PostgreSQL, per project). A
   replayed event or repeated scan queues nothing twice.
2. A bulk run drains the queue as a background job. Each object is fetched, stored once
   under the project's upload root and ingested. The original stays in the bucket; the
   image stores the reference `s3://bucket/key#etag=...`.
3. An object whose reference is already stored is `duplicate` without a download; the
   same bytes under another key are caught by the content hash.

| Trigger | What it does |
|---|---|
| Run now / `--s3` / `--source-id` | Scans, then drains the queue |
| Poll (`triggers.watch`) | Scans every `interval_s` (minimum 10); runs only if something is pending |
| Cron (`triggers.schedule`) | Scans and runs at each fire of a five-field UTC expression; a fire missed while the API was down is not replayed |
| Webhook (`triggers.webhook_enabled`) | The bucket pushes events; the route only queues rows and the dispatcher drains them within one tick |

The dispatcher is a beat tick (`jobs-beat`, run by `periodic-worker`) every
`OP_INGEST_DISPATCH_S` seconds (`0` turns every trigger off). One ingest run is live per
project; a due source waits for the next tick.

## 1. Allow the bucket

S3 is **off** until the deployment lists what may be read, in `.env`:

```bash
OP_S3_ALLOWED=my-bucket/incoming/,archive-bucket
# MinIO or another S3-compatible store:
OP_S3_ENDPOINT_URL=http://minio.example.lan:9000
OP_S3_REGION=us-east-1
OP_S3_PATH_STYLE=1
```

Each entry is `bucket` or `bucket/prefix`. Empty means every S3 route answers 503
`s3_not_configured`. A source or request outside the list is 422 `s3_not_allowed`, checked
at creation and at each use, so narrowing the list takes effect at once.

## 2. Give the API credentials

Credentials are never part of a request or a source, and the API never returns them.
boto3 finds them in the **`api` container**:

- `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` in `.env` (keep it out of version control);
- or a mounted file: `AWS_SHARED_CREDENTIALS_FILE` plus a read-only mount;
- or an instance or task role on AWS.

```yaml
# docker-compose.local.yml
services:
  api:
    environment:
      - AWS_SHARED_CREDENTIALS_FILE=/run/secrets/aws_credentials
    volumes:
      - /srv/secrets/aws_credentials:/run/secrets/aws_credentials:ro
```

Use a read-only key (`s3:ListBucket`, `s3:GetObject`) for the listed prefixes, then
`./openprocessor restart api`. Wrong credentials do not stop the API; a scan records the
error and the source reports it.

## 3. Trial run

The quickest check of allow-list, credentials and endpoint (run inside the container; the
API listens on 8000 there):

```bash
docker compose exec api python scripts/curation/bulk_ingest.py \
  --s3 s3://my-bucket/incoming/ --project my-project
```

Exit code 0 means all stored, 1 some failed, 2 the run stopped. Run it again to resume or
ingest only what is new. The same over HTTP (finds or creates a trigger-less source and
runs it; answers 202):

```bash
curl -s -X POST http://localhost:4603/curation/projects/my-project/ingest/bulk \
  -H 'Content-Type: application/json' \
  -d '{"s3": {"bucket": "my-bucket", "prefix": "incoming/"}}'
```

## 4. Register a source with triggers

Create it in Cropwright or with the API. This one polls every five minutes and accepts
S3 events:

```bash
curl -s -X POST http://localhost:4603/curation/projects/my-project/ingest/sources \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "field uploads",
    "backend": "s3",
    "s3": {"bucket": "my-bucket", "prefix": "incoming/"},
    "source": "field_uploads",
    "triggers": {
      "watch": {"enabled": true, "interval_s": 300},
      "schedule": {"enabled": false, "cron": ""},
      "webhook_enabled": true
    }
  }'
```

For a nightly run at 02:30 UTC use `"schedule": {"enabled": true, "cron": "30 2 * * *"}`.
For a folder source use `"backend": "folder", "folder": "/data/source/photos"`.

```bash
S=http://localhost:4603/curation/projects/my-project/ingest/sources
curl -s $S                                       # all sources, with queue counts
curl -s $S/<source_id>                           # one status
curl -s -X PATCH $S/<source_id> -H 'Content-Type: application/json' \
  -d '{"triggers": {"watch": {"enabled": false, "interval_s": 300},
       "schedule": {"enabled": false, "cron": ""}, "webhook_enabled": true}}'
curl -s -X POST $S/<source_id>/run               # scan and ingest now
curl -s -X POST $S/<source_id>/retry-dead        # queue given-up objects again
curl -s -X DELETE $S/<source_id>
```

A PATCH replaces `triggers` as a whole. A source's location never changes; delete it and
create another.

The status has `counts` (`pending`, `done`, `failed`, `dead`), `scan`, `watch`
(`last_poll_at`, `next_poll_at`, `error`), `schedule`, `webhook`, `last_run`, recent object
`errors`, and `can_run` with `blocked_reason` and `blocked_message` (S3 not configured,
outside the allow-list, invalid definition, or another run live).

In Cropwright use the Ingest page: **Add a source**, **Run now**, and **Retry the N that gave up**
([Ingest in Cropwright](../cropwright/user-guide/ingest.md)).

## 5. Connect the webhook

With `webhook_enabled`, the status gives `webhook.path`:

```
POST /curation/projects/{project}/ingest/sources/{source_id}/events
```

Point the store's notification target at it on the API's published address. MinIO example:

```bash
mc admin config set local notify_webhook:field \
  endpoint=http://api-host.example.lan:4603/curation/projects/my-project/ingest/sources/<source_id>/events
mc admin service restart local
mc event add local/my-bucket arn:minio:sqs::field:webhook --event put --prefix incoming/
```

The route takes the S3 event JSON (`Records[].s3.bucket.name`, `.object.key`, `.eTag`,
`.versionId`) and answers 202 `{received, queued, duplicates, ignored}`. It ignores
non-creation events and records for another bucket, prefix or file type, so one
bucket-wide notification can feed several sources. A body that is not an S3 event is 422
`invalid_s3_event`; a source without the webhook is 409 `webhook_disabled`. Delivery
from real AWS S3 has not been exercised; the AWS notification shape was replayed against
the route.

:::warning No authentication
The events route has no signature or shared-secret check (S3 sends none) and the API has
no authentication. Keep the API on loopback or a trusted LAN (`OP_BIND_ADDRESS`); do not
publish it to receive events. See [Security](../deployment/security.mdx).
:::

A webhook only reports what happens after it is set up; run the source once for objects
already in the bucket.

## Try it against a throwaway MinIO

`docker/test/compose.s3.yml` adds a MinIO server (loopback port 5392) and points `api` at
it. Use it only on a stack you may write to, under its own project name, with credentials
in a gitignored file:

```bash
C="docker compose -p <name> -f docker-compose.yml -f docker-compose.dev.yml -f docker/test/compose.s3.yml --profile s3test"
$C up -d --no-deps minio
$C up -d --no-deps api
```

Create a bucket and upload with the `mc` client, then add a source as in section 4.
Teardown: delete the project, `$C rm -sfv minio`, remove the `<name>_s3test_data` volume,
and recreate `api` without the overlay.

## Limits

| Variable | Default | Meaning |
|---|---|---|
| `OP_S3_INFLIGHT_MB` | `256` | Encoded MiB one API process holds while fetching |
| `OP_S3_MAX_OBJECT_MB` | `256` | Largest accepted object; a bigger one fails alone as `too_large` |
| `OP_S3_FETCH_WORKERS` | `8` | Download threads per API process |
| `OP_S3_LIST_WORKERS` | `8` | Sub-prefixes listed in parallel |

A scan lists 1000 keys per request and saves its position after every page, so it resumes
where it stopped; the next pass queues only what changed. Listing a very large flat bucket
costs a request per 1000 objects each pass; use the webhook there.

## Resume, failures and retries

- **Interrupted run:** a restart leaves the run `interrupted`; the next dispatcher tick (or
  your next start) resumes it and skips what is stored. A cancelled run stays cancelled
  until you start it; a failed one waits five minutes.
- **Per-object failures never fail the batch.**

  | Cause | `error_kind` | Row after |
  |---|---|---|
  | 404, `NoSuchKey`, `NoSuchVersion` | `gone` | `dead` |
  | 403, `AccessDenied`, other 4xx | `forbidden` | `failed`, retried (3 attempts in all, then `dead`) |
  | 5xx, throttling, timeout | `fetch_error` | `failed`, retried the same way |
  | over `OP_S3_MAX_OBJECT_MB` | `too_large` | `dead` |
  | not an accepted extension, empty or undecodable | decode `error_kind` | `dead` |

  `retry-dead` puts dead rows back to `pending`; a source with no trigger then needs **Run now**.
- **Where to read failures:** `GET .../ingest/bulk/{run_id}/failures` and the source's `errors`.
- **Idempotency:** starting anything twice is safe; the queue key, the stored reference and
  the content hash each drop repeats.

## Troubleshooting

| Symptom | Fix |
|---|---|
| 503 `s3_not_configured` | `OP_S3_ALLOWED` is empty, or `api` was not recreated after setting it. |
| 422 `s3_not_allowed` | The bucket or prefix is not under an `OP_S3_ALLOWED` entry. |
| 409 `bulk_ingest_busy` | A run is live in this project; wait or cancel it. |
| 409 `webhook_disabled` | PATCH the source's `triggers` with `webhook_enabled`. |
| 422 `invalid_s3_event` | The body is not an S3 event; the message names the field. |
| `watch.error` set, no runs | The scan fails (credentials, endpoint, network). The dispatcher retries with a delay doubling to ten minutes; fix the cause or call `/run`. |
| Everything `forbidden` | The key lacks `s3:GetObject` on the prefix, or endpoint and region do not match. |
| Nothing on a schedule | The API was down at the fire, or `OP_INGEST_DISPATCH_S` is `0`. |

`./openprocessor logs api -f` shows `ingest_source_poll_failed` and
`ingest_dispatch_failed` with the error.
