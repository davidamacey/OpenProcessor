# Multi-box regions

An item can have zero, one or many regions: a car crop can hold four wheels. Each box is
found, verified, embedded, clustered and labeled on its own. Every item stores its regions as
one list, `region_boxes`; one region is a list of one. There are no single-box fields.

Examples assume `API=http://localhost:4603` and project `cars`. Boxes are
`[x1, y1, x2, y2]`, normalized 0..1.

## Concepts

- **Box.** An element of `region_boxes` with `box_id`, `bbox_norm`, `bbox_in_parent`,
  `state`, `score`, `detector`, `detector_version`, `source`, `bbox_correct`, `confidence`,
  `rejection_reason`, `locked`, `thumbnail_url`, `detected_at`, text fields (`text`,
  `text_raw`, `text_source`, ...) when the profile reads text, and `cluster_*` fields.
- **`box_id`.** Stable within an item and never reused after a delete; per item, so the same
  id on two items is two boxes.
- **Frames.** `bbox_norm` is in the source image frame, `bbox_in_parent` in the item crop
  frame. A write may send `frame: "parent"` and the server projects it.
- **Box state.** `proposed` (awaiting verification), `accepted`, `rejected`,
  `false_positive`. Only accepted boxes export as positives; `false_positive` is kept as a
  hard negative. `GET .../regions/statuses` serves the vocabulary and which states each write
  route accepts.
- **Item status** follows a fixed precedence: any accepted box makes the item `detected`,
  then `false_positive`, `proposed`, `rejected`, empty.
- **Item summary fields:** `region_count`, `region_rejected_count`, `region_max_score`,
  `region_set_complete` (false when the VLM saw regions missing from the list),
  `region_revision` (optimistic-concurrency counter).
- **Locked box.** One a human created, verdicted or edited, or imported from a labeled
  dataset. Automated stages and reprocessing never touch it.
- **Caps.** `max_regions_per_item` in the [region profile](./region-profiles.mdx) (default 1,
  up to 64) after the score floor and NMS; `OP_REGION_MAX_BOXES_PER_WRITE` (default 500) per write.

## How boxes are produced

1. The region stage collects candidates from the detector and segmenter legs of the active
   profile, applies the score floor, class-agnostic NMS and the per-item cap.
2. The VLM sees the crop with each candidate drawn and numbered and returns one verdict per
   box plus whether a region is visible at all. When the profile allows more than one box,
   the [prompt pack](./prompt-packs.mdx) must name the per-box reply keys.
3. Verified boxes become `accepted`, the rest `rejected`; text is stored per box when read.
4. The embed stage writes one embedding per accepted or false-positive box to
   `region_box_embeddings`; a box a human moved is re-embedded.
5. Region clustering groups boxes, not items.

## Human edits

Replace the whole list, in display order. An element with only `box_id` leaves that box
alone; `box_id` with `bbox_norm` moves it (state kept); `box_id` with `state` changes the
state; `box_id: null` with `bbox_norm` adds a box (default `accepted`); a stored box left out
is deleted; an empty list is the human answer "no region visible".

```bash
curl -s -X PUT "$API/curation/projects/cars/crops/CROP_ID/regions" \
  -H 'Content-Type: application/json' \
  -d '{"boxes": [
         {"box_id": "b1"},
         {"box_id": "b2", "state": "rejected"},
         {"box_id": "b3", "bbox_norm": [0.10, 0.55, 0.30, 0.90]},
         {"box_id": null, "bbox_norm": [0.60, 0.55, 0.80, 0.90], "state": "accepted"}],
       "frame": "source", "expected_region_revision": 3,
       "region_label_source": "human", "region_status": null}'
```

`region_status` applies a whole-set status in the same write: `detected` (accepts every
`proposed` box; fails if none would be accepted), `false_positive` (flips every box),
`verify_rejected` (rejects every box) or `no_region_visible` (clears the list; contradicts a
non-empty `boxes`). The response is the item after the write.

One box, siblings untouched (`text` only when the profile reads text):

```bash
curl -s -X PATCH "$API/curation/projects/cars/crops/CROP_ID/regions/b2" \
  -H 'Content-Type: application/json' \
  -d '{"state": "accepted", "text": null, "expected_region_revision": 4}'
```

Item-level metadata, without touching boxes (response has `updated_fields` and `item`):

```bash
curl -s -X PATCH "$API/curation/projects/cars/crops/CROP_ID/region_meta" \
  -H 'Content-Type: application/json' \
  -d '{"region_status": "verify_rejected", "region_rejection_reason": "human"}'
```

Many items at once:

```bash
# same new boxes on each crop; [] means none visible; box_id must be null
curl -s -X PUT "$API/curation/projects/cars/crops/batch_regions" -H 'Content-Type: application/json' \
  -d '{"crop_ids": ["CROP_A", "CROP_B"], "boxes": [], "region_status": null}'
# one state on named boxes across items
curl -s -X POST "$API/curation/projects/cars/regions/batch_box_state" -H 'Content-Type: application/json' \
  -d '{"state": "false_positive", "targets": [{"crop_id": "CROP_A", "box_id": "b1"}], "expected_region_revisions": {"CROP_A": 4}}'
# one item-level status on every box of many items (max 5000 crops)
curl -s -X POST "$API/curation/projects/cars/regions/batch_status" -H 'Content-Type: application/json' \
  -d '{"crop_ids": ["CROP_A", "CROP_B"], "region_status": "false_positive"}'
```

Batch responses list `updated`, `conflicts`, `invalid` and the post-write rows in `items`.

Ask the VLM to judge boxes with an assist run (`POST .../assist/runs`, action `verify`),
target `{"kind": "boxes", "boxes": [{"crop_id": "CROP_ID", "box_id": "b2"}]}` or a `crops`
target for every box. Human- or import-owned boxes are never sent. Action `attributes`
stores the pack's `box` attributes (a wheel's rim material) in the item's `assist` object.

Box thumbnail (`size` 32 to 512, default 128):

```bash
curl -s -o box.jpg "$API/curation/projects/cars/crops/CROP_ID/region_thumbnail?box_id=b1&size=128"
```

## Undo

Each human region write can be undone; repeated calls step back.

```bash
curl -s -X POST "$API/curation/projects/cars/crops/CROP_ID/region/undo"
curl -s -X POST "$API/curation/projects/cars/crops/region/undo_batch" \
  -H 'Content-Type: application/json' -d '{"crop_ids": ["CROP_A", "CROP_B"]}'
```

The single call returns the restored item; the batch returns `items`, `undone`,
`nothing_to_undo`, `conflicts` and `not_found`. See also
[Label operations and undo](./label-operations-and-undo.mdx).

## Browse, cluster, false positives

Box routes return one row per matching box, with `region_box_id`; filters apply to the same box.

| Call (under `/curation/projects/{project}`) | Purpose |
|---|---|
| `GET /regions` | Rows. Filters: `detector`, `min_score`, `max_score`, `text`, `cluster_uid`, `box_state`, `status`, `class_id`, `verified`, `max_rank` |
| `GET /regions/statuses`, `GET /regions/vocabulary` | Statuses and box states; vocabulary and write limits |
| `GET /regions/clusters` | Cluster cards: `size` (items), `box_count`, representatives |
| `POST /regions/fp_centroids/build` | Build false-positive centroids from `false_positive` boxes |
| `GET /regions/suspected_false_positives` | Boxes ranked by distance to a false-positive sub-centroid |
| `GET /regions/training_candidates` | `mode`: `detector_blind_spots`, `low_conf_correct`, `disagreement`, `human_corrected`, `false_positives` |

A page has `items`, `page`, `page_size`, `total` (items), `total_rows` (rows) and
`rows_truncated` (an item matched more boxes than the index returns).

```bash
curl -s "$API/curation/projects/cars/regions?box_state=accepted&min_score=0.5&page_size=50"
```

A clustering run rebuilds false-positive sub-centroids, flips tight matches to
`false_positive`, then partitions the good boxes. Human-final items and locked boxes are never
changed. After marking more false positives, rebuild the centroids.

## Errors

| Status | `error` | When |
|---|---|---|
| 409 | `region_conflict` | Stale `expected_region_revision`; body has `current_region_revision`, `current_box_ids`, the current `item` |
| 409 | (undo) | No human region write left to undo |
| 422 | `too_many_boxes` | Over the per-write cap (`limit`, `requested` returned) |
| 422 | `region_text_disabled` | `text` on a profile that reads no text |
| 422 | `box_id_in_batch` | A batch element with a `box_id` |
| 422 / 404 | `box_id_required` / `unknown_box_id` | Thumbnail without a `box_id`, or one the crop does not hold |
| 422 | (message) | `bbox_norm` out of range or degenerate, new box without `bbox_norm`, state the route does not accept, `no_boxes` / `no_accepted_box` for `detected` |
