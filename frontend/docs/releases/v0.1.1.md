# Cropwright v0.1.1

**Cropwright 0.1.1 adopts the OpenProcessor 0.4.1 API: promoting a model to Triton now runs as a background job you can watch, leave and come back to, cluster cards show label agreement, and prompt packs get a proper denylist editor.** It also fixes boxes drifting off the image in the box editor.

This release requires **OpenProcessor backend v0.4.1** (curation API contract at backend commit `c984fd8c`).

## What's new

### Promote runs as a background job

- `POST /train/promote/{job_id}` is now a `202` job in OpenProcessor 0.4.1 instead of a 2 to 3 minute blocking call. The promote dialog follows the served phases (queued, exporting, loading, building, warming) and shows the result on `done`, or the served error with its status on `failed`.
- Closing the dialog leaves the job running. Reloading the page re-opens the dialog on a running promote.
- A double click or a `409 promote_in_progress` follows the job already running rather than failing.
- Gate failures no longer repeat the class prefix (`object:object: precision ...` is now `object: precision ...`).

### Cluster cards show label agreement

- Cluster cards read the served `label_agreement` for label quality. Geometry-only `purity` and `purity_tier` are unchanged. A backend that does not serve it falls back to `label_purity`.
- The first open of a very large cluster shows a loading hint instead of an empty grid.

### Denylist editor in prompt packs

- `proposal_denylist` (case-insensitive glob patterns) is edited as a list: add and remove rows, entries are trimmed, blanks and case-insensitive duplicates are dropped, at most 500 entries of 200 characters, and the served validation issue shows on the field.
- The editor picks the list control from the served field `kind`, not the field id. An unknown future `kind` is shown read-only and saved unchanged.

### Detector delete prompt

- Deleting a model that is the project's ingest detector (`409 detector_in_use`), or hitting `503 config_store_unavailable`, shows the served reason and offers a confirmed force retry instead of a bare error toast.

### Fixes

- **Box alignment.** Boxes now line up with the image in the box editor and the crop detail modal. Drawn or moved boxes no longer save shifted coordinates, and the detail modal no longer shows a stretched black box.
- **Removed routes.** The app and its test stubs no longer reference the removed single-box region write routes; a source scan keeps it that way.
- **Promote error text.** See the class-prefix fix above.

## Compatibility

- **Minimum backend: OpenProcessor v0.4.1.** The promote flow expects the `202` job response and the `promote` object on `GET /train/status/{job_id}`. Cropwright 0.1.1 does not carry a compatibility path for the blocking `200` promote of v0.4.0, so against v0.4.0 the promote dialog will not track progress correctly. Upgrade the backend first. The other changes (denylist editor, label agreement with `label_purity` fallback) degrade gracefully on older backends.
- The contract is verified against backend `c984fd8c`. Since the earlier snapshot the only contract change is an additive optional `force` query parameter on promote.
- Docker with Compose v2; images are multi-arch (linux/amd64, linux/arm64).

## Known issues

- **Stale Safari cache.** After an upgrade Safari can keep serving old bundles and show images that do not load. Hard-refresh (Cmd-Shift-R) or open a private window.
- **Docs service is opt-in.** `/cropwright/` returns 502 unless you start the docs profile (`docker compose --profile docs up -d`).

## Upgrade instructions

1. Upgrade OpenProcessor to v0.4.1 first.
2. `docker compose pull && docker compose up -d` (or re-run the OpenProcessor installer, which pins this release by tag and digest).
3. Hard-refresh the browser (Cmd/Ctrl-Shift-R).

Pin a version with `CROPWRIGHT_TAG=0.1.1`, or a digest with `CROPWRIGHT_IMAGE=davidamacey/cropwright@sha256:...`. Cropwright holds no state, so rollback is re-pinning the previous tag or digest (and the matching backend).
