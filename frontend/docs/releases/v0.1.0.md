# Cropwright v0.1.0

**Cropwright is a browser workbench for curating and labeling image crops: review what your detectors found, cluster it, fix it, and turn it into a trained model, all against an OpenProcessor backend.** This is the first public release.

Cropwright is a stateless SvelteKit web app served by nginx. It has no database of its own: every project, crop, cluster and setting is read from, and written back to, the OpenProcessor curation API.

## Highlights by theme

### Projects and lifecycle

- Switch between projects from the top bar; every page is project-scoped (`/p/<slug>/...`).
- Create, clone from another project (copy settings, classes and profiles), copy settings between projects, and delete with a dry-run first that shows exactly what would go.
- Project administration screens for health, settings and per-project resources.

### Dashboard

- Per-project overview: counts, review progress, embedding state, and the served resource links.
- Embedding-state row shows per-crop embedding coverage so you know what clustering will see.

### Clusters, crops review and labeling

- Cluster cards with purity, dominant class, validated counts and representative crops; open a cluster to review, relabel, reject or move crops in bulk.
- Active-learning review queues (mismatches, low-confidence VLM labels, outliers, uncertainty, model disagreements).
- Box editor for adjusting and adding boxes; multi-box regions with a region gallery.
- Item filter, shift-select bulk actions, and locked-item badges so human decisions survive reprocessing.

### Keyboard-first workflow

- A complete keymap with per-class hotkeys from the served class list; reserved keys are respected.
- Settings page to review and remap shortcuts.

### Regions and region profiles

- Region stage, region review tab and region gallery driven by a served region profile.
- Region-profile editor with a **test panel** (shows `testable: false` and the served reason when a profile cannot be tested) and a segmenter prompt check.

### Open vocabulary and prompt packs

- Open-vocabulary editor and test panel, and prompt-pack editor and test, so you can add classes by text prompt and see the effect before committing.

### VLM configuration and test

- VLM endpoint editor, per-run VLM model picker, and an endpoint test.

### Dataset import, combine and export

- Import wizard for labeled datasets (preview, name-based class mapping, options, confirm-gated start) and a job view with served progress and Cancel / Resume / Undo that follow the backend's allowed actions.
- Combine wizard to merge projects into a new one, with a job view.
- Export with the frozen class registry and manifest.

### Train, promote and runs

- Training launch with preflight checks, run results with a confusion matrix, model bake-off, promote/share/unshare (with a forced-unshare confirmation) and a model inventory card.

### Resources menu

- A top-bar Resources menu renders exactly the links the backend serves (docs, services, status and hints), with a client-owned Documentation entry.

### Reprocess and locks

- Reprocess dialog with served scopes and vocabulary; locked items are skipped and badged.

### Documentation

- A bundled documentation site (`davidamacey/cropwright-docs`) with a screenshot for every major screen. All screenshots are captured from public sample projects (COCO val2017, plus Open Images for the plate-review screens) (see `docs-site/static/img/screenshots`).

## Requirements

- **OpenProcessor backend v0.4.0** (curation API contract sha `5df30815`). Cropwright does nothing useful without a running backend.
- Docker with Compose v2. Images are multi-arch (linux/amd64, linux/arm64).
- A modern browser (Chrome, Edge, Firefox, Safari).

## Install and run

**With the OpenProcessor installer (recommended).** The installer pins this release by tag and image digest, downloads `docker-compose.yml`, `.env.example` and `SHA256SUMS` from this release, verifies them, and runs Cropwright next to the backend on the backend's docker network. The web UI is on port **5184** and, by default, binds to all interfaces so other machines on your LAN can reach it (`--local-only` binds 127.0.0.1).

**Standalone.**

```bash
curl -LO <release>/docker-compose.yml
curl -L  <release>/.env.example -o .env
# set API_UPSTREAM, PUBLIC_API_PREFIX (= backend OP_API_PREFIX), OP_DOCKER_NETWORK
docker compose pull && docker compose up -d          # app on :5184
docker compose --profile docs up -d                  # optional: bundled docs at /cropwright/
```

Open `http://localhost:5184`. Pin a version with `CROPWRIGHT_TAG=0.1.0`, or a digest with `CROPWRIGHT_IMAGE=davidamacey/cropwright@sha256:...`.

**Reverse proxy and LAN.** The browser only talks to the Cropwright origin; nginx proxies `PUBLIC_API_PREFIX/*` to the API, so there is no CORS to configure. nginx forwards `Host`, `X-Forwarded-Host`, `X-Forwarded-Proto` and the client address, so a TLS-terminating proxy in front of port 5184 works. The curation API has no authentication: keep Cropwright on a trusted network and never expose it to the internet. The image runs nginx as uid 101 (non-root) on container port 8080 with all capabilities dropped. Upload caps are `CROPWRIGHT_INGEST_MAX_REQUEST_MB` (default 256) and `CROPWRIGHT_DATASET_UPLOAD_MAX_MB` (default 2048).

## Known issues

- **Stale Safari cache.** After an upgrade Safari can keep serving old bundles and show images that do not load. Hard-refresh (Cmd-Shift-R) or open a private window.
- **Large clusters open slowly the first time.** The first open of a very large cluster can take several seconds; the page shows a loading hint instead of an empty grid.
- **Docs service is opt-in.** The bundled docs are not started by default, so `/cropwright/` returns 502 until you run with `--profile docs` (the OpenProcessor installer stack reads the public docs site instead).

## Upgrade notes

This is the first release; there is nothing to migrate. For later upgrades: `docker compose pull && docker compose up -d`, then hard-refresh the browser. Cropwright holds no state, so rollback is just re-pinning the previous tag or digest.

## Verifying the release

`SHA256SUMS` covers `docker-compose.yml` and `.env.example`. The installer additionally pins the `davidamacey/cropwright` image by digest; `docker buildx imagetools inspect davidamacey/cropwright:0.1.0` shows the multi-arch manifest.
