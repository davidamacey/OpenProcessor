# Architecture diagram sources

`specs/*.json` are hand-authored [Archify](https://github.com/tt-a1i/archify) diagram
specifications — architecture, workflow, and sequence types — built from real repo evidence
(`src/routes/`, `src/lib/api.ts`, the controllers under `src/lib/*/*Controller.svelte.ts`, the
slot registry, `nginx.conf`, `docker-compose.yml`, etc.). They are **not** generated by a
static-analysis tool — they describe how this specific SvelteKit app and its OpenProcessor
backend actually fit together, verified by reading the code.

Rendered output lives in `docs-site/static/architecture/*.html` and is served at
`/architecture/<name>.html`, embedded via `docs-site/src/pages/architecture.tsx`.

## Regenerating

Requires the Archify Claude Code skill (MIT license):

```bash
npx skills add tt-a1i/archify -g
```

Then, from the repo root:

```bash
scripts/generate-architecture-diagrams.sh                  # all specs
scripts/generate-architecture-diagrams.sh system-overview   # just one
```

The script validates each spec at `showcase` quality before delivering — a spec that fails
validation is never silently rendered broken.

## Diagrams

| Group     | id                    | Type         | What it shows |
| --------- | --------------------- | ------------ | -------------- |
| System    | `system-overview`     | architecture | Browser → Cropwright nginx → OpenProcessor API → OpenSearch/Triton/VLM/trainer/segmenter, plus the vendored wire contract. |
| System    | `frontend-modules`    | architecture | Routes, controllers, runes stores, the slot registry (served region profile + tier-2 profiles), `api.ts`, and the contract tests. |
| Workflows | `labeling-loop`       | workflow     | Ingest → clustering/VLM → clusters → review → classes → export/holdout → train → bake-off → promote → probe predictions feeding back into review. |
| Workflows | `ingest-upload`       | workflow     | The browser upload run controller: `path_lookup` prefilter, chunk planning, bounded-concurrency upload, 413/422/503 handling, the region-drain gate, and the clustering handoff. |
| Sequences | `review-assign-undo`  | sequence     | A `/review` keypress → optimistic queue update → API write (with rollback on failure) → the Z undo round trip through `undoStore`. |

## Updating a diagram

Treat a stale diagram the same as any other doc: when the code it describes changes, edit the
matching `specs/*.json` and re-run the generator. Do not hand-edit the rendered HTML in
`static/architecture/` — it is a build artifact and will be silently overwritten.
