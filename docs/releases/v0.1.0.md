# OpenProcessor v0.1.0

First public release.

OpenProcessor is a backend for computer-vision dataset curation and training,
with a fast inference API underneath. Ingest images, detect and crop regions,
label them with people and a vision-language model (VLM), import and combine
datasets, export, train and promote models. It works for any image domain.
The optional web UI, Cropwright, is a separate frontend for the same API.

## Highlights

**Inference API** (port 4603, `/v1` twin for the core routes), on NVIDIA Triton
with TensorRT engines:
- Object detection (YOLO11 and YOLO26), batches of up to 64 images.
- Face detection, ArcFace embeddings, verify, search and identify.
- MobileCLIP embeddings and visual search over OpenSearch k-NN.
- PP-OCRv5 text detection and recognition.

**Curation and training** (`/curation`, project scoped):
- Isolated projects: own indexes, directories, class registry, settings and
  jobs, enforced at the OpenSearch transport layer.
- Versioned prompt packs and region profiles (create, activate, roll back,
  test on stored crops) and per-project keymaps.
- One or many regions per item, each with its own state, text, cluster and vector.
- VLM endpoint registry with a local model catalog; remote endpoints need an
  explicit acknowledgement because crops leave the host.
- Dataset import (YOLO, COCO, OpenProcessor export) with preview, by-name class
  mapping, undo and resume; unified `/reprocess`; combine up to eight projects.
- Class identity by name everywhere; human labels and the test holdout are
  never overwritten by an automated writer.
- Review queues, clustering, semantic search, export, training jobs, model
  bake-off and promotion.
- One-line installer with digest-pinned images and checksum-verified assets.

## Pre-release notes

- The versions in `CHANGELOG.md` headed `Pre-release` were private history.
  v0.1.0 is the first public version; there is no upgrade path from them.
- k-NN indexes use OpenSearch derived source. Indexes created by pre-release
  builds with it disabled must be recreated (fresh installs only).

## Requirements

- Linux, Docker with Compose v2, an NVIDIA GPU (Ampere or newer) with driver 535+
  and the NVIDIA Container Toolkit. The installer never installs packages.
- VRAM: about 16 GB for `core` (6-8 GB cards use `--profile minimal`); the
  `curation`, `segmenter`, `vlm` and `trainer` tiers add to that
  (README, Tiers). 16 GB RAM minimum, 32 GB recommended.
- Disk: about 60 GB for `core`, about 135 GB for every tier (the Triton image
  alone is about 30 GB), plus 20 GB headroom.
- Storage sizing: about 8.4 KB per vector on disk, and about 22 KB per image at
  1.3 detections per image (details: `docs/opensearch_schema_design.md`).

## Quick start

```bash
curl -fsSL https://raw.githubusercontent.com/davidamacey/OpenProcessor/main/setup-openprocessor.sh | bash
```

Pin this release with `bash -s -- --version v0.1.0`; add `--dry-run` to see every
command first. To verify the download yourself, fetch `setup-openprocessor.sh` and
`SHA256SUMS` from this release and run `sha256sum --check`
(README, "Verify the download yourself"). Then open
`http://localhost:4603/docs`. Full guide: `INSTALLATION.md`.

## Known limitations

- The region stage runs SAM 3 inside an already-detected item's crop. Full-image,
  open-vocabulary SAM 3 detection is not available yet (#30).
- 12 GB cards such as the RTX 3080 Ti run the minimal profile; their TensorRT
  engine builds use a smaller workspace and are less tuned than on 48 GB cards.
- Images are large (tens of GB for the first pull).
- The installer installs published releases only; it needs this release's assets
  and images. Before then, a source checkout uses `scripts/setup.sh`.
- Cropwright screenshots in the docs are marked pending.
