# OpenProcessor v0.5.0

The monorepo release. The backend and its web UI, Cropwright, now live in this one
repository (`frontend/`, formerly a separate repository), are built, tested, pinned and
released together, and share one documentation site. The release also delivers label
confirmation (#119), the one-port gateway (#93), the optional detector hint for VLM
labeling (#61 item 2), a refreshed dependency set (FastAPI, Pydantic, SvelteKit,
TypeScript, MLflow 3, PyTorch 2.14.1) and the file splits of #168. Everything in v0.4.1
is unchanged in kind. Two changes are breaking and one changes what a running daemon does;
they come first.

## Breaking and behaviour changes since 0.4.1

State plainly, because a script, an override file or a stored document may depend on them:

- **The compose service `yolo-api` is now `api`** (#62). Every
  `docker compose exec|logs|restart yolo-api`, `./openprocessor logs|restart yolo-api`,
  override file, script and dashboard that names the old service must change to `api`.
  The Prometheus job and the Loki service label are `api` too. The container name
  (`<project>-api`), the `op-api` network alias and all data volumes are unchanged.
  Because the old container holds the same name, an existing install must be brought up
  with `docker compose up -d --remove-orphans`; `./openprocessor upgrade`, the installer,
  `make up` and `scripts/setup.sh` pass it for you.
- **The unread `DetectionProfile` fields `ocr_det_model`, `ocr_det_version`,
  `ocr_det_input_size` and `ocr_det_prob_floor` are removed** (#181), together with the
  dead `PaddleOcrRegionDetector`. This is a wire change: a stored or submitted region
  profile that still carries one of those keys is **rejected** with `profile_field_unknown`
  (the message names the key). Delete the keys from the document. The value stamped as
  `region_text_engine_version` is now `<rec model>:<version>` instead of
  `<det>:<ver>+<rec>:<ver>`. The `/ocr` endpoint's `OCR_DET_MODEL` is unchanged.
- **Auto-promote is gated on the accuracy audit** (#119). `POST /clusters/auto_promote` and
  the `auto_label` auto-promote stage promote a class only with enough audited crops and an
  audited detector precision of at least `promote_min_precision` (default 0.95); otherwise
  they answer `409 audit_required` or `409 audit_precision_low` and write nothing.
  `force=true` bypasses the gate (logged); a dry run is never gated. The
  `curation-cluster-refresh` daemon therefore promotes nothing until the audit clears a
  class.
- **MLflow moves to 3.17, server and trainer together** (#120). An existing `mlflow_data`
  volume upgrades in place on first start and old runs, artifacts and registered models stay
  readable. MLflow 3 answers `403 Invalid Host header` for any `Host` outside its allowed
  list; the compose file sets a list of the in-network names plus localhost and private-IP
  defaults. Browsing MLflow by a DNS name needs `MLFLOW_ALLOWED_HOSTS` (it replaces the whole
  list; see `env.template`).
- The segmenter image is rebuilt on PyTorch 2.14.1 and Ubuntu 24.04 (Python 3.12). SAM 3
  outputs match the previous image.
- The contract changes are additive except the profile fields above: new `/vlm/policy` and
  `/audit/*` routes, the `detector_*` item fields, `kind: "int"` in the pack schema, and
  `pack_field_out_of_range`. `scripts/codegen/generate_contracts.py --check` is clean.

## Highlights

**One repository, one docs site (#85)**
- Cropwright is in `frontend/` with its scrubbed history (merged, not squashed; the
  `cropwright-v0.1.0` and `cropwright-v0.1.1` tags are kept). It is the opt-in `cropwright`
  compose profile on the stack's own network and is built from `frontend/Dockerfile`.
  Its tests read the generated `contracts/` directory, so a backend wire change fails a
  frontend test.
- Its image (`davidamacey/cropwright`) is the sixth image built by `make release` and is
  pinned in `images.lock` like the others. `cropwright.lock`, the `<project>-cw` second
  compose project and the staged Cropwright files in the deploy tarball are gone.
- Cropwright now follows the monorepo version (0.5.0; its standalone 0.1.x numbering ends at
  0.1.1). The Cropwright documentation is a section of the one docs site.

**Gateway: the monitoring UIs on the one port (#93)**
- `OP_GATEWAY_SUBPATHS=true` (set it in `.env`; there is no installer flag) makes Cropwright's
  nginx serve Grafana, Prometheus, OpenSearch Dashboards and MLflow under `/grafana/`,
  `/prometheus/`, `/dashboards/` and `/mlflow/` of its single published port, so the UIs stay
  on `127.0.0.1`. The API serves path-relative `resource_links` and MLflow run links in this
  mode. With the switch off (the default) those four paths answer 404.
- Fail closed: the UIs refuse to start when published beyond loopback, and Grafana refuses the
  default or an empty admin password. Prometheus and MLflow still have no authentication.

**Label confirmation (#119, backend and UI)**
- A VLM label is a suggestion until a human validates it. `GET/PUT /vlm/policy` sets, per
  project, which crops the automated VLM writers may label (`all`, the unchanged default,
  `uncertain`, `representatives` or `off`, plus a daily budget and a sample fraction).
- The detector's own class, confidence and class id are kept on the item beside the VLM or
  human label (`detector_class_name`, `detector_confidence`, `detector_class_id`); items
  ingested before this release have none (no backfill). A `detector_disagreements` review tab
  lists unvalidated items whose VLM class differs from the detector's.
- The accuracy audit (`POST /audit/start`, `GET /audit/queue`, `GET /audit/report`) draws a
  deterministic stratified sample of machine-labelled crops and reports per-class detector and
  VLM precision with Wilson 95% intervals, the confusion matrix and an `insufficient_sample`
  flag. The auto-promote gate above reads it.
- Cropwright shows all of this: a VLM scope panel on `/settings`, the detector class beside a
  VLM label with "VLM suggestion", "Human-confirmed" and "Auto-validated" wording, the
  Detector Disagreements tab on `/review`, a new `/audit` page, and a note on `/export` that
  only validated crops are exported.
- The VLM worker and the `auto_label` sweep no longer select frozen-holdout or excluded items.
- Two follow-up fixes ship with it: the `representatives` scope is bounded by persisted
  per-cluster claims (`vlm_scope_reps`, #192), and `detector_disagreements` lists the least
  confident VLM answers first (no recorded confidence, then low, medium, high, #195; the
  "Uncertain only" copy now says what the selector does).
- Live-verified on COCO 200 images, GPU 0 (first pass, before the follow-up fixes): the
  scope-policy counts, the detector class stored beside every VLM label, the
  `detector_disagreements` count, the human-label lock, the holdout freeze and the export
  (73 validated crops), the audit report against a manual count, and the `auto_promote` gate
  codes.
- Second live pass over the fixes on the merged tree (COCO 200 images, 1,367 crops, local
  VLM, GPU 0): the `representatives` scope with `per_cluster=5` attempted exactly the bound
  (893 against 893 with stable clustering, 856 against 856 with the refresh daemon running;
  the first pass attempted 1,237 against 438); a worker restart and a policy revision bump
  after the pass did not re-open the pool (a restart during a pass was not tested). The
  `detector_disagreements` tab ordered 169 items low, medium, high with no inversion (items
  with no recorded VLM confidence, which sort first, were not present in the data). Scope
  `uncertain` attempted 896 crops, exactly the crops with detector confidence below 0.8 or
  none. Twenty clone-then-read loops of a prompt pack all read back immediately. The dashboard
  "Last clustering" card shows the time and method after a worker-driven run. Full-page
  screenshots at 1600 px and 430 px of settings, the disagreements tab, audit, export,
  dashboard and clusters were viewed: no horizontal overflow, clipping, `null` or `undefined`.
- **Measured VLM labeling throughput** (plan step V1, local VLM on one GPU, batches of 32
  crops, 8 request threads): 10.0 crops/s over 200 crops in 20 s with no errors; the
  continuous worker averaged 9.8 crops/s over 1,277 crops.

**Detector hint for VLM labeling (#61 item 2)**
- A prompt pack's `detector_hint_min_confidence_pct` (int 0-100, 0 = off, **the default**)
  adds each item's stored detector class name and confidence to the VLM prompt as a one-line
  hint when the detector confidence is at least that percent. Replies are parsed as before; a
  value outside 0-100 is rejected with `pack_field_out_of_range`.
- Measured on a public COCO oracle (local VLM, 200 images, 539 scored crops): overall
  accuracy rose from 0.7755 to 0.8534 and accuracy when answered from 0.8496 to 0.9182. In a
  second project seeded with validated classes overall accuracy rose from 0.7846 to 0.8478.
  Run-to-run noise is about 0.5 point. Caveat: the detector is COCO-trained and the oracle is
  COCO ground truth, so the gain may be optimistic for other domains; generalisation beyond
  COCO is an open item for 0.6.0.
- The default proposal-name denylist is broader (scene and quality words such as `abstract*`,
  `*_background`, `scene*`, `empty*`, tested so no glob eats a COCO class). Strict-glob
  proposal noise measured 1-3% on the main arms and 4.9% on the seeded arm with the hint on.

**Dependency refresh**
- FastAPI 0.143 and Pydantic 2.14 (contracts regenerated), SvelteKit 3 and
  `adapter-static` 4 on TypeScript 6, MLflow 3.17, Playwright 1.63, the backend group
  (opencv-python-headless, pytest 9.1, pytest-playwright), `aiohttp>=3.14.4`,
  `locust>=2.46.7`, nginx-unprivileged 1.31, PyTorch 2.14.1 for the segmenter. `onnx` and
  `huggingface-hub` 2.x are held back on purpose (their dependents pin lower versions).

**Maintainability (#168, #62, #174)**
- No source file under `src/` or `scripts/` is over 700 lines and the size hook has no
  exemptions: the OpenSearch clients, export, VLM labeler, worker runner, train router,
  training jobs, ingest and search routers, cascade detection, clustering orchestrator and
  three services were split into cohesive modules with no route or wire change. Unused
  public symbols (`ITEMS_CLUSTER_INDEX`, `assign_cluster_to_crop`) were deleted.

**Smaller fixes**
- A clean install no longer leaves the default detector (`yolov11_small_trt_end2end`) unavailable: the
  installer seeds an FP32 `det_boxes`/`det_scores` config while the TensorRT 11 engine builds FP16,
  and a kept config now takes the built engine's output dtypes.
- Cropwright pages no longer overflow horizontally at 430 px (#184): the top bar and the
  `/review` tab strip wrap, and a hidden table header on `/projects` no longer widens the page.
- `scripts/lib/download.sh` and `export_paddleocr.sh` found the running container by its bare
  service name, which never matched, so they always started a temporary container; both now
  resolve it through compose (#187).
- `/health` no longer takes about 3 s when the optional VLM is not running.
- Cropwright's nginx redirects use relative `Location` headers.

## Upgrade instructions from 0.4.1

- Upgrade with `./openprocessor upgrade` (or `./setup-openprocessor.sh --version v0.5.0`). It
  backs up first, passes `--remove-orphans`, and `--rollback` restores the newest backup.
  For a hand-run compose install: `docker compose pull` then
  `docker compose up -d --remove-orphans`.
- Rename `yolo-api` to `api` in every script, override file and dashboard of your own.
- Delete `ocr_det_model`, `ocr_det_version`, `ocr_det_input_size` and `ocr_det_prob_floor`
  from any stored or submitted region profile (and from `examples/region_profiles/` copies).
- Cropwright now ships in `images.lock`. If you installed it as a second compose project
  (`<project>-cw`) with 0.4.1, the upgrade replaces that with the `cropwright` profile of the
  main project; stop the old one with `docker compose -p <project>-cw down` if it is left
  running. Cropwright 0.5.0 requires backend 0.5.0.
- Rebuild or pull the segmenter and the trainer images. MLflow data upgrades in place; if you
  browse MLflow by a DNS name, set `MLFLOW_ALLOWED_HOSTS`.
- To use the gateway, set `OP_GATEWAY_SUBPATHS=true` in `.env` and restart; publish the
  monitoring UIs on loopback only and use a non-default Grafana admin password.
- Decide whether `curation-cluster-refresh` auto-promotion should resume: run the audit
  (`POST /audit/start`, then label the queue), or call auto_promote with `force=true`.
- Hard-refresh the browser (Ctrl/Cmd-Shift-R) after upgrading; Safari can serve a stale
  cached bundle.

## Requirements

Unchanged from 0.4.1.

- Linux, Docker with Compose v2, an NVIDIA GPU (Ampere or newer) with driver 535+ and the
  NVIDIA Container Toolkit. The installer never installs packages.
- VRAM about 16 GB for `core` (6-8 GB cards use `--profile minimal`); the `curation`,
  `segmenter`, `vlm` and `trainer` tiers add to that. 16 GB RAM minimum, 32 GB recommended.
- Disk about 60 GB for `core`, about 135 GB for every tier, plus 20 GB headroom.
- `vm.max_map_count` of at least 262144 (the installer warns and prints the fix).

## Quick start

```bash
curl -fsSL https://raw.githubusercontent.com/davidamacey/OpenProcessor/main/setup-openprocessor.sh | bash
```

Pin this release with `bash -s -- --version v0.5.0`; add `--dry-run` to see every command
first. To verify the download yourself, fetch `setup-openprocessor.sh` and `SHA256SUMS`
from this release and run `sha256sum --check --ignore-missing SHA256SUMS`. Then open
`http://localhost:4603/docs`. Full guide: `INSTALLATION.md`.

## Known issues

- **The API has no authentication.** Do not expose it; see `SECURITY.md`. The gateway and the
  Cropwright port inherit this.
- **Grafana keeps the default `admin` password on LAN-only installs**; change it before
  exposing the stack beyond your LAN. (Gateway mode refuses the default.) Prometheus and
  MLflow have no authentication.
- **A clean-host install from the published artifacts has not yet been run (#44).** It stays
  open until it is run against the published 0.5.0 assets.
- **The 430 px fix is covered by the stubbed e2e suite only.** It has not been checked against
  a live backend on a phone-sized viewport.
- **The per-item detector hint may not generalise beyond COCO** (the measured gain used a
  COCO-trained detector against COCO ground truth); validating it on other domains is open for
  0.6.0. It is off by default.
- **VLM labels are unvalidated suggestions** and are never trainable or holdout-eligible
  until a human validates them. The default VLM scope is still `all`; set `/vlm/policy` to
  `uncertain`, `representatives` or `off` to limit it.
- Follow-ups filed from #119 and the dependency work, none blocking: #166 (the audit fields are not yet on the item wire), #161 (`FileJob.read`
  treats an unreadable state file as idle), #154 (the trainer still uses deprecated MLflow
  registry stages), #153 (`ORJSONResponse` deprecation), #155 (SvelteKit `config.alias`
  deprecation), #101 (pin the VLM connection to the validated IP).
- **Trivy, accepted classes** (allowlisted per CVE with a reason in
  `scripts/release/trivy-allowlist.txt`, re-checked every release): libxml2 `CVE-2026-6653`
  and `linux-libc-dev` kernel headers (headers only, no kernel runs in a container, no
  upstream fix). The mlflow 2.x allowlist entries are gone with the MLflow 3 move.
- The first open of a very large cluster can be slow until the background `cluster_distance`
  backfill finishes. Safari may show a stale cached bundle after an upgrade.
- Cropwright's `/OpenProcessor/` documentation route answers 502 unless the docs container
  (`docker-compose.docs.yml`) is running.

## Verification summary

- **Scripted acceptance run** (`make acceptance`, isolated install of the release-candidate images
  through the real installer, one GPU): 19 of 19 required phases passed (health, self-hosted docs,
  ingest of 100 COCO images, detect and embed, clustering, VLM labeling, human confirmation,
  holdout, export, a 2-epoch probe train, bake-off, forced promote, inference, model delete,
  metrics, log noise, teardown). The run found one product defect, fixed before release: a clean
  install left the default detector unavailable (FP32/FP16 output config mismatch, see Smaller fixes).
  Not demonstrated in this run: the installer re-run, repair, upgrade and uninstall phases (the
  re-run phase needs a GPU with enough free memory for the full model set; they are covered by
  the installer test suite and the 4 Oct 2026 installer acceptance), and the VLM model switch.
- **Full gate on the release line:** 7,350 offline tests passed (14 skipped),
  `pre-commit run --all-files` clean, contracts in sync, `make release-verify` passed (untouched
  assets verify, a tampered tarball and a tampered installer are refused), `make release-dry-run`
  built and Trivy-scanned all six images with no un-allowlisted CRITICAL finding; CI (pre-commit,
  offline suite, frontend check/unit/e2e, image and repository scans) was green on every merged
  pull request.
