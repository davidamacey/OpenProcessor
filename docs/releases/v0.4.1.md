# OpenProcessor v0.4.1

Patch release on v0.4.0. Everything in v0.4.0 (the generic, any-domain curation and
training backend with the Triton inference API underneath) is unchanged in kind. This
release repairs CI, adds the operator metrics and dashboards that were missing, turns
promote into a background job, adds the first label-confirmation quick wins, fixes the
installer and VLM-switch problems found by live testing, ships a scripted release
acceptance run and real documentation screenshots, and carries the fixes that live
verification of all of it on a running stack turned up. The optional web UI,
Cropwright 0.1.1, requires this backend and ships staged in the deploy bundle.

## Breaking and behaviour changes since 0.4.0

State plainly, because a script or UI may depend on them:

- **`POST /curation/projects/{project}/train/promote/{job_id}` now returns `202`** with a
  `promote_id` and runs the export, load and warm-up as a background job. Poll
  `GET .../train/promote/{job_id}/jobs/{promote_id}`. Add `?wait=true` for the previous
  blocking `200` response (it needs a client timeout of at least 300 s and is for
  scripts that call the API directly). Behind a reverse proxy, use the `202` job and
  polling: proxies time out near 120 s. A repeat promote of a run with an active job
  returns that job.
- **`DELETE .../models/{name}` refuses a project's own ingest detector** with
  `409 detector_in_use` unless `force=true`, so a delete cannot silently break ingest.
- **The promoted model name carries the project**: it is served as
  `<project>__<requested triton_name>` (no prefix for `default`); the final name is
  returned as `triton_name` in the promote result and job status and is the name
  `/detect?model_name=` and `DELETE /models/{name}` expect. This is behaviour from
  0.4.0 that is now documented (#129).
- **Project delete is asynchronous and a deleted slug is retired.** The call answers
  `202` `deleting`, the project answers `404` a few seconds later, and creating the same
  slug again answers `slug_retired` (#130).
- `GET .../crops` returns `n_unembedded` only for `order=diverse` or `core_first`
  (null otherwise); use `GET .../stats/dataset` `embedding` to watch an embed drain (#130).
- The contract change is additive: one optional `force` query parameter on promote, and
  description-only edits. `scripts/codegen/generate_contracts.py --check` is clean.

No data migration is needed from 0.4.0.

## Highlights

**CI repaired (#121)**
- `main` was red: the offline suite now installs every dependency the not-live tests use
  (including `opensearch-py[async]`) and pins the FastAPI and pydantic versions the
  committed OpenAPI contract is generated from; the pre-commit job installs the app
  dependencies for the contract hook; the Trivy steps honour
  `scripts/release/trivy-allowlist.txt`; patched `lodash-es`, `serialize-javascript` and
  the `sockjs` uuid are pinned in docs-site; the API image no longer ships pip (its
  vendored msgpack, setuptools and urllib3 were flagged by the image scan). CI and the
  Security Scan are green on the release line.

**Observability (#94, #123, #124)**
- Fourteen new operator `op_*` metrics: per-project ingest images and items, queue depth
  and oldest-item age, embedding state, worker heartbeat and up, segmenter
  hit/miss/error counts and latency, detection worker items, VLM tokens and latency,
  and OpenSearch shards and store bytes per project.
- The detection, VLM and auto-label workers are scraped by Prometheus; Alloy ships the
  worker and segmenter container logs (`job="worker"`).
- New panels in the Overview, Ingest pipeline and API and curation dashboards.
- Found and fixed by live verification: the queue, embedding-state and OpenSearch gauges
  now populate (#123); `op_ingest_*` carries the real project slug, and the
  `OP_METRICS_MAX_PROJECT_LABELS` cap ranks live projects only (#124).

**Promote as a background job (#87, #128)**
- `202` plus a job with phases `queued`, `exporting`, `loading`, `building`, `warming`,
  `done` or `failed`; the latest promote appears as `promote` in
  `GET .../train/status/{job_id}`. A `?wait=true` promote no longer stops mid-load when
  the connection drops. `force` may now be sent as `?force=true` as well as in the body.

**Label confirmation quick wins (#61, part of the plan)**
- Cluster cards serve `label_agreement` (equal to `label_purity`) so label quality is
  not read from the geometric `purity`.
- Prompt packs take an optional `proposal_denylist` (glob patterns such as `blurry_*`)
  that drops matching new-class proposals; the generic pack ships a starter list. Create,
  save, clone and validate keep and validate it (#125). The remainder of the plan is
  0.5.0 work.

**Installer and VLM switching (#111, #126, #127)**
- A CUDA out-of-memory during an export step is a permanent `oom` failure with a
  `--gpu-plan` hint instead of a retried transient (#111); an explicit
  `--gpu-plan triton=N` onto a card with under 16 GB free is refused unless `--force`,
  and the automatic plan warns.
- `openprocessor vlm use` credits the running VLM container's own VRAM, so a legitimate
  switch is no longer refused (#126); the pause sentinel records its owner and the GPU
  arbiter leaves one it did not create alone, so workers stay paused during the model
  load (#127). `vlm use|probe` without `OP_LOCAL_VLM_ENDPOINT` explains how to enable the
  in-compose VLM.

**Scripted acceptance run (#54)**
- `make acceptance` (`scripts/release/acceptance_run.sh`) drives health, docs, ingest,
  clustering, VLM labeling, confirmation, holdout, export, a 2-epoch probe train,
  bake-off, promote, inference, model delete, metrics, log-noise checks, VLM switch and the
  installer lifecycle against an isolated install, with a JSON report and a cleanup trap
  that always removes the throwaway project and promoted models.

**Detector delete guard (#75)**
- See the behaviour changes above. A developer-guide note explains restarting the API after
  pulling (`make dev-restart`).

**Docs**
- 24 real screenshots from the public COCO sample projects replace the Cropwright
  placeholders (#43); market research and competitive analysis and the label
  confirmation plan are linked from the docs index; promote naming, async project delete
  and `n_unembedded` are documented in the guides, the API reference and
  `docs/CURATION.md` (#129, #130).

**Smaller fixes**
- Startup legacy-project repair logs at info only when it repaired rows, instead of one
  line per project per worker (#92).
- Trainer status writes use a unique temporary file per writer, so the heartbeat cannot
  race the terminal status write.
- The COCO car manifest pin test always checks the tracked manifest (#103); the installer
  dry-run test and a new pin test cover the committed `images.lock` and `cropwright.lock`.

## Upgrade instructions from 0.4.0

- `./openprocessor upgrade` (or `./setup-openprocessor.sh --version v0.4.1`). It
  backs up first; `--rollback` restores the newest backup. There is nothing to migrate.
- Update any script that calls promote: poll the job, or add `?wait=true`.
- Hard-refresh the browser (Ctrl/Cmd-Shift-R) after upgrading; Safari can serve a stale
  cached bundle.
- Upgrade Cropwright with the backend: Cropwright 0.1.1 requires backend 0.4.1.

## Requirements

Unchanged from 0.4.0.

- Linux, Docker with Compose v2, an NVIDIA GPU (Ampere or newer) with driver 535+ and the
  NVIDIA Container Toolkit. The installer never installs packages.
- VRAM about 16 GB for `core` (6-8 GB cards use `--profile minimal`); the `curation`,
  `segmenter`, `vlm` and `trainer` tiers add to that. 16 GB RAM minimum, 32 GB recommended.
- Disk about 60 GB for `core`, about 135 GB for every tier, plus 20 GB headroom.
- `vm.max_map_count` of at least 262144 (the installer warns and prints the fix).

## Quick start

```bash
curl -fsSL https://raw.githubusercontent.com/davidamacey/OpenProcessor/main/setup-openprocessor.sh | bash
```

Pin this release with `bash -s -- --version v0.4.1`; add `--dry-run` to see every command
first. To verify the download yourself, fetch `setup-openprocessor.sh` and `SHA256SUMS`
from this release and run `sha256sum --check --ignore-missing SHA256SUMS`. Then open
`http://localhost:4603/docs`. Full guide: `INSTALLATION.md`.

## Known issues

- **Trivy, accepted classes** (allowlisted per CVE with a reason in
  `scripts/release/trivy-allowlist.txt`, re-checked every release): libxml2
  `CVE-2026-6653`; `linux-libc-dev` kernel headers (headers only, no kernel runs in a
  container, no upstream fix); the trainer's `mlflow` 2.x pin (a 3.x move needs client and
  server together, #110).
- **VLM labels are unvalidated suggestions** and are never trainable or holdout-eligible
  until a human validates them. The continuous VLM worker labels every unlabelled embedded
  crop by default; pause it with `POST /curation/projects/{project}/pause` or stop the
  `curation-vlm-worker` service. Scope control (`all`, `uncertain`, `representatives`,
  `off`), a budget and an accuracy audit are planned for 0.5.0 (#119).
- The first open of a very large cluster can be slow until the background
  `cluster_distance` backfill finishes.
- Safari may show a stale cached bundle after an upgrade; hard refresh fixes it.
- Cropwright's `/cropwright/` documentation route answers 502 unless its compose `docs`
  profile is enabled; the installer starts only the `cropwright` service.
- Grafana keeps the default `admin` password on LAN installs; change it before exposing the
  stack beyond your LAN.
- A clean-host install from the published artifacts has not yet been run (#44).
